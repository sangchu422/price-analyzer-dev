작성일: 2026-07-24

## 1. 검토 목적

이 프로젝트는 회사가 실제로 수령한 협력사 견적서를 정제해 내부 표준단가 DB를 구축하고, 신규 견적의 가격 적정성을 검토하기 위한 시스템이다.

이번 로컬 작업에서는 기존 코드와 문서, 견적서 원본을 점검하고 신규 로컬
아키텍처의 데이터 기반, 정제 규칙, 자동 표준 DB, 신규 견적 업로드·분석
API와 웹 화면까지 구현했다.

## 2. 확정된 기준

### 데이터의 의미

- 내부 표준 DB는 외부 시장가 DB가 아니다.
- 회사가 실제로 받은 **과거 견적서**의 품목·규격·단가를 현재 시스템이
  직접 정제·집계한 내부 견적 이력 DB다.
- 기존 `표준단가DB.xlsx`는 초창기 수작업 산출물이므로 입력, 검증, 비교,
  내보내기, 증빙으로 사용하지 않는다.
- 내부 DB에서 동일·유사 품목이 검색되면 과거 견적 단가를 우선 비교한다.
- 내부 매칭이 없거나 근거가 약할 때 외부 API·가격 비교 사이트·크롤링 결과를 보조 근거로 사용한다.
- 외부 시장가는 내부 표준단가와 별도 데이터로 저장한다.
- 신규 검토 결과는 담당자 승인 후 표준단가 갱신 후보가 된다.

### 구축 방향

- A 구조: `React + FastAPI + SQLite` 기반의 로컬 우선 구성
- 서버 설치와 사내 배포는 로컬 기능 검증 후 진행
- 향후 사내 임베딩 API를 연결할 수 있도록 공급자 어댑터와 환경변수 자리만 우선 마련
- 임베딩 API 규격과 샘플 코드는 사용자가 사내 환경에서 추후 제공
- 품목 검색은 정규화·키워드·퍼지 검색을 기본으로 하고, 임베딩을 결합하는 하이브리드 방식
- 가격 검토 근거와 표준단가 갱신 이력에는 원본 파일, 시트·행 또는 PDF 페이지, URL, 조회 일시, 이미지 등의 증빙을 보존

`견적서/` 아래에서 확인한 논리 원본은 총 36개이며, 보호 원본과 보안해제 복사본을 각각 증빙 변형으로 세면 물리 파일은 48개다.

| 상태 | 수량 | 설명 |
|---|---:|---|
| XLSX 물리 파일 | 37 | 보안해제 복사본 포함 |
| 구형 XLS | 7 | 로컬 신규 파서의 지원 대상 |
| PDF | 4 | 총 130페이지, 텍스트 추출 및 렌더링 가능 |
| 보안해제 복사본 | 15 | 파싱 우선 변형. 보호 원본과 한 쌍인 논리 문서는 12개 |

기존에 분석할 수 없던 파일은 사용자가 파일명 뒤에 `_보안해제`를 붙인 `.xlsx` 복사본으로 저장했다. 현재 사전 점검에서는 15개 논리 문서에서 보안해제본이 파싱 우선 변형으로 선택된다.

보호 원본은 증빙으로 보관한다. 파싱 단계에서는 동일 논리 문서의 `_보안해제.xlsx`를 우선 선택하고 보호 원본과 중복 적재하지 않는다. 견적서 원본과 보안해제본은 로컬 증빙이며 코드 커밋에 포함하지 않는다.

### 초기 루트 파서에서 확인됐던 누락

다음은 루트의 초기 시제품 `parse_all.py`에 대한 과거 감사 결과다. 현재
`backend/app` 파이프라인은 별도 구현이며 루트 파서를 운영 경로로 사용하지
않는다.

- 초기 파서는 `.xlsx`와 `.pdf`만 검색하고 `.xls`를 제외했다.
- 파일명이 하드코딩된 메타데이터 목록에 없으면 조용히 건너뛰었다.
- 일부 PDF와 `테스트.xlsx`가 하드코딩 목록 때문에 반영되지 않았다.
- 일부 XLSX는 갑지·집계표만 있고 세부 품목 시트가 없어 표준가격 근거로
  부족했다.

## 4. 기존 Excel과 현재 표준 DB의 관계

기존 `표준단가DB.xlsx`는 과거에 수작업으로 만든 초창기 참고 파일이다.
현재 시스템은 이 파일을 읽거나 대조하지 않으며, 그 집계값을 결과 검증이나
가격 판정에 사용하지 않는다. 기존 Excel 형식으로 내보내는 기능도 없다.

현재 표준 DB의 유일한 가격 출처는 현재 SQLite에 적재된 과거 견적서의
원본 행이다. 원본 파일 SHA-256, 시트·행·셀 또는 PDF 페이지, 파서 버전과
정제 결정을 함께 보존하므로 화면에서 가격 근거를 역추적할 수 있다.

## 5. 로컬 A 구조 구현 및 실제 코퍼스 결과

### 실행 방법

현재 단계는 로컬 전용이다. 서버 설치와 사내 배포는 기능 검증 이후로 미룬다.

```powershell
cd backend
python -m app.cli preflight --quote-root ..\견적서
python -m app.cli preflight --quote-root ..\견적서 --json
python -m app.cli ingest --quote-root ..\견적서 `
  --database-file .local\price-analyzer.sqlite3 `
  --report .local\corpus-run.json
```

- `preflight`는 파일 내용을 열지 않고 확장자, 논리 문서, 보안해제 우선순위, 경로·증빙 이슈만 점검한다.
- `ingest`는 지정 SQLite에 Alembic 마이그레이션을 적용하고 논리 문서별 독립 트랜잭션으로 적재한다.
- 보호 원본/보안해제 쌍은 둘 다 해시 증빙으로 등록하지만, 내용 파서는 보안해제 우선 파일만 호출하고 짝이 있는 보호 원본은 건너뛴다.
- 보안해제 짝이 없는 일반 원본은 읽을 수 있고 지원 양식이면 그 원본을 파싱한다.
- JSON 보고서에는 견적서 루트의 절대경로를 기록하지 않고 상대 논리 이름과 안정된 오류 코드만 기록한다.
- 적재 실패도 DB 트랜잭션은 롤백하되 보고서에 우선 파일 및 모든 변형의 상대경로·SHA-256을 남긴다. 해시를 읽을 수 없으면 `HASH_UNAVAILABLE`로 기록한다.
- `.local/`, SQLite와 실행 보고서는 Git 제외 대상이다.
- SQLite DB와 실행 보고서는 견적서 루트 내부나 원본 파일의 링크·별칭으로 지정할 수 없다.
- 종료 코드는 `0=전체 성공`, `1=문서별 일부 실패`, `2=경로·로컬 설정 실패`다.

## 9. 자동 표준 DB와 신규 견적 분석

### 자동 구축 규칙

```powershell
cd backend
..\.venv\Scripts\python -m app.cli standard-db-build `
  --database-file .local\standard-item-migration-v2.sqlite3
```

- 최신 역할이 `HISTORICAL_REFERENCE`인 문서의 최신 `INCLUDED` 행만 사용한다.
- 정규화된 `품명 + 사양 + 단위` 완전 일치 그룹을 만든다. 단위는 그룹 키의
  일부이므로 다른 단위는 별도 표준품목이다.
- 근거 1건 그룹도 사용하며 화면에 `근거 1건` 경고를 표시한다.
- 빈 품명과 단위 충돌은 제외 사유로 보고서에 기록한다.
- 동일 fingerprint와 규칙 버전의 성공 실행은 재사용한다. 재실행 시
  표준품목·멤버십·가격을 중복 생성하지 않는다.
- 현재 표준품목, 멤버십, 가격만 화면에 표시하지만 과거 결정은 삭제하지
  않는다. 정정은 새 결정과 새 가격 버전을 추가하는 방식이다.
- 기존 수동 멤버십과 충돌하면 임의로 덮어쓰지 않고 전체 자동 구축을
  롤백한다.
- `REVIEW_REQUIRED`인 판정대기 행은 자동 포함·삭제하지 않고 설비구매팀이
  추후 검토한다.

### 신규 견적 웹 흐름

1. `/analysis`에서 새 견적서 `.xlsx`, `.xls` 또는 `.pdf`를 업로드한다.
2. 파일은 별도 증빙 저장소에 SHA-256으로 보존되고 문서 역할은
   `INCOMING_BID`가 된다.
3. 최신 정제 결과가 준비되면 현재 표준 DB와 완전 일치하는 행을 비교한다.
4. 표준 평균 대비 가격을 `낮음`, `적정`, `높음`, `검토 필요`로 표시하고
   원본 행과 표준가격 증빙을 함께 보여준다.
5. 완전 일치하지 않는 후보와 판정대기는 설비구매팀이 검토한다.

분석은 읽기 전용이다. 신규 견적 행은 표준 DB 구축 입력에서 제외되며,
분석이나 후보 새로고침은 멤버십·표준가격을 생성하지 않는다.

실제 운영 DB를 오염시키지 않기 위해 업로드 E2E는 복사본
`backend/.local/task9-validation.sqlite3`에서만 수행했다. 샘플 견적서
1건에서 원본 행 1,492건, 분석 가능 `INCLUDED` 232건을 확인했다.
232건은 완전 일치 표준가격으로 판정됐으며 분석 전후 멤버십 6,603건,
표준가격 2,468건, 가격 관측 6,603건이 모두 그대로였다. 검증 업로드는
`backend/.local/task9-validation-submissions/`에 보존되어 있다.

## 10. 후속 작업과 사내 인수인계

### 아직 연결하지 않는 기능

- hChat 임베딩은 환경변수와 어댑터 자리만 준비되어 있다. 가정망·로컬에서
  호출하지 않는다. `HCHAT_EMBEDDING_ENABLED`,
  `HCHAT_EMBEDDING_ENDPOINT`, `HCHAT_EMBEDDING_API_KEY`,
  `HCHAT_EMBEDDING_MODEL`, `HCHAT_EMBEDDING_API_STYLE`은 사내망에서만
  실제 값으로 설정한다.
- DeviceMart·Mouser는 시장가를 미리 수집해 별도 DB를 구축하고, 캐시에
  없는 품목만 실시간 조회하는 후속 단계다. 링크, 조회시각, 원본 이미지 등
  근거를 반드시 보존한다.
- 서버 설치, 조직 인증, 사내 배포는 로컬 기능 검토 뒤 진행한다.
- Excel 내보내기는 요구사항이 아니다. 신규 견적 접수와 판정은 웹에서 한다.
