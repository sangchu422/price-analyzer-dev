작성일: 2026-07-24
대상 저장소: `sangchu422/price-analyzer-dev`

## 1. 검토 목적

이 프로젝트는 회사가 실제로 수령한 협력사 견적서를 정제해 내부 표준단가 DB를 구축하고, 신규 견적의 가격 적정성을 검토하기 위한 시스템이다.

이번 로컬 작업에서는 기존 코드와 문서, 견적서 원본, 표준단가 Excel DB의 현황을 점검했다. 이어서 신규 로컬 아키텍처의 데이터 기반, 정제 규칙, 검토 API·화면, 코퍼스 이관 CLI까지 구현했다.

## 2. 확정된 기준

### 데이터의 의미

- `표준단가DB`는 외부 시장가 DB가 아니다.
- 회사가 실제로 받은 **과거 견적서**의 품목·규격·단가를 정제·집계한 내부 견적 이력 DB다.
- 내부 DB에서 동일·유사 품목이 검색되면 과거 견적 단가를 우선 비교한다.
- 내부 매칭이 없거나 근거가 약할 때 외부 API·가격 비교 사이트·크롤링 결과를 보조 근거로 사용한다.
- 외부 시장가는 내부 표준단가와 별도 데이터로 저장한다.
- 신규 검토 결과는 담당자 승인 후 표준단가 갱신 후보가 된다.

### 구축 방향

- A 구조: `React + FastAPI + SQLite` 기반의 로컬 우선 구성
- 서버 설치와 사내 배포는 로컬 기능 검증 후 진행
- 향후 사내 임베딩 API를 연결할 수 있도록 공급자 어댑터와 환경변수 자리만 우선 마련
- 임베딩 API 규격과 샘플 코드는 사용자가 사내 환경에서 추후 제공
- 품목 검색은 정규화·키워드·퍼지 검색을 기본으로 하고, 임베딩을 결합하는 하이브리드 방식
- 가격 검토 근거와 표준단가 갱신 이력에는 원본 파일, 시트·행 또는 PDF 페이지, URL, 조회 일시, 이미지 등의 증빙을 보존

## 3. 원본 견적서 감사 결과

`견적서/` 아래에서 확인한 논리 원본은 총 36개이며, 보호 원본과 보안해제 복사본을 각각 증빙 변형으로 세면 물리 파일은 48개다.

| 상태 | 수량 | 설명 |
|---|---:|---|
| XLSX 물리 파일 | 37 | 보안해제 복사본 포함 |
| 구형 XLS | 7 | 로컬 신규 파서의 지원 대상 |
| PDF | 4 | 총 130페이지, 텍스트 추출 및 렌더링 가능 |
| 보안해제 복사본 | 15 | 파싱 우선 변형. 보호 원본과 한 쌍인 논리 문서는 12개 |

기존에 분석할 수 없던 파일은 사용자가 파일명 뒤에 `_보안해제`를 붙인 `.xlsx` 복사본으로 저장했다. 현재 사전 점검에서는 15개 논리 문서에서 보안해제본이 파싱 우선 변형으로 선택된다.

보호 원본은 증빙으로 보관한다. 파싱 단계에서는 동일 논리 문서의 `_보안해제.xlsx`를 우선 선택하고 보호 원본과 중복 적재하지 않는다. 견적서 원본과 보안해제본은 로컬 증빙이며 코드 커밋에 포함하지 않는다.

### 현재 파서에서 확인된 누락

- 현재 `parse_all.py`는 `.xlsx`와 `.pdf`만 검색하며 `.xls`를 제외한다.
- 파일명이 하드코딩된 메타데이터 목록에 없으면 파일을 조용히 건너뛴다.
- 분석 가능한 PDF 3개, 총 86페이지가 현재 DB에 반영되지 않았다.
- `테스트.xlsx`는 실제 가격 행을 포함하지만 하드코딩 목록에 없어 반영되지 않았다.
- `data/260408-평택블록OP60편심기준핀외견적서.xls`는 정상적으로 열리지만 현재 검색 범위와 확장자 조건에서 제외된다.
- 일부 XLSX는 갑지·집계표만 있고 세부 품목 시트가 없어 표준단가 원본으로 부족하다.

## 4. 현재 표준단가 DB 감사 결과

현재 `표준단가DB.xlsx`는 원본 견적 행 4,246건과 집계된 표준단가 1,852건으로 구성되어 있다.

주요 확인 사항:

- 표준단가 1,852건 중 1,317건(71.1%)은 근거 견적이 1건뿐이다.
- 규격 누락은 965건(52.1%), 메이커 누락은 1,304건(70.4%)이다.
- 현재 분류 값은 모든 행이 `설비`로 고정되어 있다.
- 품목명 띄어쓰기, 영문 대소문자, 기호 차이로 같은 품목이 별도 그룹으로 집계된다.
- 1원 단가, `이 윤`이 품목으로 들어간 행, 단위 열에 품목명이 들어간 열 밀림 사례가 있다.
- 현재 집계는 `품목명 + 규격 + 단위`의 완전 일치와 단순 산술평균을 사용한다.
- 원본 파일명, 시트명, 행·셀 주소, 파싱 버전, 파싱 신뢰도, 검토 상태가 없어 결과를 원본까지 추적하기 어렵다.
- 화면 설명의 협력사 수와 실제 원본 데이터의 공급업체 문자열 수가 일치하지 않는다.

이 DB는 초기 검색과 데모에는 사용할 수 있지만, 품질 검증 없이 자동 가격 판정 또는 자동 표준단가 갱신의 확정 기준으로 사용하면 안 된다.

## 5. 로컬 A 구조 구현 및 실제 코퍼스 결과

### 실행 방법

현재 단계는 로컬 전용이다. 서버 설치와 사내 배포는 기능 검증 이후로 미룬다.

```powershell
cd backend
python -m app.cli preflight --quote-root ..\견적서
python -m app.cli preflight --quote-root ..\견적서 --json
python -m app.cli ingest --quote-root ..\견적서 `
  --database-file .local\price-analyzer.sqlite3 `
  --report .local\corpus-run.json
```

- `preflight`는 파일 내용을 열지 않고 확장자, 논리 문서, 보안해제 우선순위, 경로·증빙 이슈만 점검한다.
- `ingest`는 지정 SQLite에 Alembic 마이그레이션을 적용하고 논리 문서별 독립 트랜잭션으로 적재한다.
- 보호 원본/보안해제 쌍은 둘 다 해시 증빙으로 등록하지만, 내용 파서는 보안해제 우선 파일만 호출하고 짝이 있는 보호 원본은 건너뛴다.
- 보안해제 짝이 없는 일반 원본은 읽을 수 있고 지원 양식이면 그 원본을 파싱한다.
- JSON 보고서에는 견적서 루트의 절대경로를 기록하지 않고 상대 논리 이름과 안정된 오류 코드만 기록한다.
- 적재 실패도 DB 트랜잭션은 롤백하되 보고서에 우선 파일 및 모든 변형의 상대경로·SHA-256을 남긴다. 해시를 읽을 수 없으면 `HASH_UNAVAILABLE`로 기록한다.
- `.local/`, SQLite와 실행 보고서는 Git 제외 대상이다.
- SQLite DB와 실행 보고서는 견적서 루트 내부나 원본 파일의 링크·별칭으로 지정할 수 없다.
- 종료 코드는 `0=전체 성공`, `1=문서별 일부 실패`, `2=경로·로컬 설정 실패`다.

### 2026-07-25 실제 파일 읽기 전용 실행

원본 파일은 이동·수정·삭제하지 않았으며, 별도 로컬 SQLite에 최초 적재 후 같은 명령을 한 번 더 실행했다.

| 항목 | 최초 실행 관측값 |

| 논리 문서 | 36 |
| 보안해제 우선 문서 | 15 |
| 보호 원본과 보안해제본 쌍 | 12 |
| DB 등록 증빙 변형 | 47 |
| 적재 성공 / 실패 | 35 / 1 |
| 원시 견적 품목 | 28,598 |
| 최신 `INCLUDED` | 6,604 |
| 최신 `EXCLUDED` | 21,668 |
| 최신 `REVIEW_REQUIRED` | 326 |
| 기본 정제 결정 신규 | 28,598 |
| 그룹 MAD 이상치 결정 신규 | 107 |

지원 물리 파일은 48개지만 실패 문서의 그룹 트랜잭션 전체를 롤백하므로 DB 증빙 변형은 47개다. 실패한 우선 파일과 변형의 상대경로·해시는 별도 실행 보고서에 남는다. 최신 상태 합계는 원시 품목 28,598건과 일치한다.

실패는 다음 한 건이다.

| 상대 논리 이름 | 오류 코드 | 판단 |
|---|---|---|
| `2차 학습/2016년 견적서2 7.업체견적서` | `UNSUPPORTED_LAYOUT` | 35쪽 PDF의 내장 글꼴 문자 매핑이 깨져 품명·단가 헤더와 행을 안전하게 판별할 수 없음. OCR 또는 별도 PDF 추출 프로필이 필요함 |

억지로 행을 추정해 오적재하지 않고 실패로 격리했다. 다른 35개 논리 문서는 정상 반영됐다.

- 신규 증빙 변형 `0`

- 신규 기본 정제 결정 `0`

## 9. 2026-07-26 표준품목·내부가격 분석 이관

기존 정제 검토 페이지는 그대로 유지한다. `판정대기` 행은 자동 삭제하거나
자동 그룹에 넣지 않으며, 추후 설비구매팀이 검토한다.

### 로컬 명령

```powershell
cd backend

# 현재 INCLUDED 중 품명·사양·단위가 완전히 같은 행이 2건 이상인 경우만 생성
.venv\Scripts\python -m app.cli catalog-seed `
  --database-file .local\price-analyzer.sqlite3

# 로컬 개발용 mock 인덱스. 실제 의미 임베딩으로 오해하면 안 됨
.venv\Scripts\python -m app.cli embedding-index `
  --database-file .local\price-analyzer.sqlite3 `
  --index-file .local\standard-items-mock.npz `
  --mock

# 계산 초안만 출력하며 표준단가 버전을 승인하지 않음
.venv\Scripts\python -m app.cli standard-price-drafts `
  --database-file .local\price-analyzer.sqlite3
```

보고서는 기본적으로
`backend/.local/reports/<명령>-<UTC시각>-<run-id>.json`에 매번 새로
저장되며 출력의 `report_file`에서 실제 상대경로를 확인할 수 있다.
`--report backend/.local/...json`을 명시하면 해당 파일을 교체하므로,
고정 파일이 필요한 자동화에서만 사용한다.

세 명령의 DB·보고서·인덱스 경로는 모두 프로젝트의
`backend/.local` 내부 일반 파일만 허용한다. 디렉터리, 심볼릭 링크,
Windows junction/reparse point, 서로 같은 파일이나 hard link,
견적 원본의 경로·별칭·동일 SHA-256 파일은 실행 전에 거부한다.
따라서 원본 XLSX/PDF를 DB나 보고서 경로로 잘못 지정해도 덮어쓰지 않는다.

자동 생성 규칙은 `EXACT_RULE_V1` 하나뿐이다. 현재 최신 정제 결정이
`INCLUDED`여야 하고, 정규화된 품명·사양·단위가 완전히 같아야 하며,
그룹에 최소 2개 행이 필요하다. 같은 품명·사양에서 단위가 충돌하면
자동 생성하지 않는다. 기존 수동 결정이 있는 행도 덮어쓰지 않는다.
퍼지 검색과 임베딩 검색은 후보만 반환하고 `MATCHED` 결정을 만들지 않는다.
자동 멤버십 증빙에는 `rule_version=EXACT_RULE_V1`과
`normalization_version=match-v1`을 함께 기록한다.

`standard-price-drafts`는 읽기 전용이다. 초안 계산은 현재 INCLUDED이면서
현재 승인된 그룹 멤버십이 있는 행만 사용한다. 실제
`StandardPriceVersion` 생성은 화면/API에서 사람 이름과 최신 fingerprint를
확인한 명시적 승인으로만 가능하다.

한 INCLUDED 행은 정규화 가능한 품명이 없어 자동 그룹 대상에서 제외됐다.
공급사와 견적일 메타데이터는 아직 문서별 버전으로 입력되지 않았으므로
현재 초안의 공급사 수와 최신 견적일은 신뢰할 수 없다. 이 정보는 사내
검토에서 보강해야 한다. 깨진 글꼴 매핑 PDF 한 건은 이전과 동일하게
`UNSUPPORTED_LAYOUT`으로 격리됐다.

같은 DB에서 재실행했을 때 신규 표준품목과 멤버십은 모두 0건이었다.
mock 인덱스는 `local-mock-v1`, 1,178개 항목으로 생성됐으며
`network_called=false`, `automatic_approval=false`였다. `--mock`을 빼면
로컬 설정은 `DISABLED`로 종료되고 인덱스를 만들지 않았다.

### 사내 hChat 연결 순서

로컬 또는 가정망에서 hChat을 호출하지 않는다. 사내 API 샘플을 받은 뒤
`backend/app/embeddings/hchat.py`의 `_build_payload`와 `_parse_response`
두 codec 경계만 샘플 계약에 맞춘다. 먼저
`backend/tests/embeddings/test_hchat_adapter.py`의 mock transport 계약
테스트만 실행하고, 통과한 뒤 사내망에서 별도 인덱스 파일을 만든다.
API 키는 환경 변수로만 주입하며 로그·보고서·Git에 기록하지 않는다.

DeviceMart·Mouser의 캐시 우선 시장가 DB, 원본 링크·조회시각·이미지 증빙,
캐시에 없는 항목의 실시간 조회는 다음 독립 계획 범위다.
