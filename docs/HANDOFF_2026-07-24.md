# 로컬 개발 인수인계

기준일: 2026-07-27

현재 구현 기준은 저장소 루트 `README.md`와 `CLAUDE.md`다. 제품은
React + FastAPI + SQLite 구조이며 서버 설치는 아직 범위 밖이다.

## 사내 Claude 첫 작업 체크리스트

아래 순서로 현재 구현을 확인한다. 구형 프로토타입을 실행하거나 DB를 먼저
재생성하지 않는다.

아래 명령은 저장소 루트에서 `cmd.exe`로 실행한다. PowerShell과 `.ps1`은
사내 정책상 사용하지 않는다.

```bat
git fetch origin
git switch feature/market-price-integration
git pull --ff-only origin feature/market-price-integration
git status --short

scripts\start-local.bat --validate-only
scripts\start-local.bat
```

1. `git status --short`가 비어 있는지 확인한다.
2. 로컬 DB가 비어 있으면 첫 실행이 추적 중인 `견적서` 원본으로 표준 DB를
   자동 구축할 때까지 기다린다.
3. `http://127.0.0.1:8000/api/health`가 정상인지 확인한다.
4. `http://127.0.0.1:4173/standard-prices`에서 표준 DB를 확인한다.
5. `http://127.0.0.1:4173/analysis`에서 신규 견적 복사본을 업로드해
   결과를 확인한다.
6. hChat 임베딩은 사내망에서 연결 확인이 완료됐다. 사외망 실패를 구현
   오류로 판단하지 않는다.

Claude 작업 시 다음 사항을 지킨다.

- `archive/legacy-excel-prototype/`의 코드는 실행하거나 현재 코드에 다시
  연결하지 않는다.
- `표준단가DB.xlsx`를 입력·검증·비교·내보내기·증빙에 사용하지 않는다.
- 실제 로컬 DB를 삭제·초기화하지 않는다. 데이터 변경 검증은 DB 복사본에서
  먼저 수행한다.
- 신규 견적은 표준 DB 멤버십이나 가격 근거로 추가하지 않는다.
- DeviceMart 공개 검색과 Mouser Search API 기반 시장가 캐시·증빙 기능은
  `feature/market-price-integration` 브랜치에 구현되어 있다.
- hChat 임베딩은 구현 완료 (`.env`에 `HCHAT_EMBEDDING_*` 설정 필요).
- 서버 설치는 후속 범위다.
- 리뷰에서는 `Critical`과 `Important`만 우선 수정하고 `Minor`는 보고한다.

## 확정 업무 흐름

- 과거 견적은 `HISTORICAL_REFERENCE`로 수집한다.
- 최신 `INCLUDED` 행만 품명·사양·단위로 그룹화해 표준 DB와 표준가격을
  자동 구축한다. 근거 1건도 허용하되 화면에 경고한다.
- 신규 견적은 `/analysis`에서 업로드하며 `INCOMING_BID` 역할을 가진다.
- 신규 견적 행은 표준 DB 멤버나 표준가격 관측값으로 사용할 수 없다.
- 표준 DB와 정확 매칭되면 가격을 비교하고, 가격 근거나 매칭이 없으면
  검토 대기로 남긴다.
- 기존 수작업 Excel은 현재 시스템에서 사용하지 않는다.

## 단일 로컬 DB

모든 명령과 서버는 아래 경로 하나를 사용한다.

```text
backend\.local\standard-item-migration-v2.sqlite3
```

```bat
set "DATABASE_FILE=%CD%\backend\.local\standard-item-migration-v2.sqlite3"

cd backend
..\.venv\Scripts\python.exe -m alembic current
..\.venv\Scripts\python.exe -m alembic check
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe -m app.cli standard-db-build --database-file "%DATABASE_FILE%"
cd ..
```

DB가 없는 신규 환경에서는 `alembic upgrade head`가 빈 스키마를 만든다.
그 뒤 루트 `README.md`의 `ingest`와 `standard-db-build` 절차로 초기화한다.

## 시장가 기능 사용법

1. `.env`의 `MOUSER_API_KEY`에 Mouser Search API 키를 입력한다.
2. 백엔드에서 `python -m alembic upgrade head`를 실행해 `0009`를 적용한다.
3. 신규 견적을 `/analysis`에 첨부한다.
4. 내부 표준 DB에 매칭되지 않은 행의 `시장가 조회`를 누른다.
5. 7일 이내 저장 결과가 있으면 캐시를 사용하고, 없거나 만료되면 DeviceMart와
   Mouser를 조회해 새 증빙을 저장한다.
6. 결과 카드에서 `원본 상품 보기`, `수집 증빙 보기`, 상품 사진과 수집 시각을
   확인한다.

시장가 데이터는 내부 표준단가 테이블과 분리되어 있으며
`backend/.local/evidence/market/`에 API JSON 또는 검색 JSON, 상품 이미지,
선택적 화면 캡처를 저장한다. DeviceMart는 공개
`/goods/search_sse_stream`의 `sphinx_result`만 사용하며 배너 HTML은 가격
근거로 사용하지 않는다. 두 출처가 모두 실패하거나 모델 토큰이 맞지 않으면
가격을 만들지 않고 판정대기로 둔다.

## 다른 PC에서 pull 후 최초 DB 구축

로컬 SQLite DB와 `backend/.local/` 실행 보고서는 Git에 올리지 않는다.
따라서 새 PC에서는 아래 순서로 추적 중인 1·2·3차 견적 원본을 다시 파싱해
DB를 만들어야 한다. 명령은 저장소 루트의 `cmd.exe`에서 실행한다.

```bat
git switch feature/market-price-integration
git pull origin feature/market-price-integration

py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -e backend
call npm.cmd --prefix frontend install

scripts\start-local.bat --validate-only
scripts\start-local.bat --initialize-only
```

`--initialize-only`는 다음 작업을 순서대로 수행한다.

1. `backend/.local/standard-item-migration-v2.sqlite3` 생성
2. Alembic 최신 마이그레이션 적용
3. `견적서/` 아래 1·2·3차 원본 적재와 정제
4. 최신 `INCLUDED` 행으로 표준품목과 표준가격 재구축
5. `backend/.local/reports/standard-db-build-latest.json` 보고서 저장

일부 원본은 위 실패 사유 때문에 적재 경고가 발생하는 것이 현재 정상이다.
실행기는 안전하게 파싱된 행으로 계속 표준 DB를 구축한다. 완료 후 화면까지
실행하려면 다음 명령을 사용한다.

```bat
scripts\start-local.bat
```

확인 주소:

- 웹 분석: `http://127.0.0.1:4173/analysis`
- API 상태: `http://127.0.0.1:8000/api/health`
- 기대 기준: 표준품목 약 6,946개, 가격 관측 근거 약 19,668개

동일 PC에서 다시 `--initialize-only`를 실행하면 데이터가 있는 DB는 재구축하지
않는다. 완전 재구축이 필요할 때도 운영 DB를 임의 삭제하지 말고 먼저 백업한
뒤 별도 DB 경로로 검증한다.
