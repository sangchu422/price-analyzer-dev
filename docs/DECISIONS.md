# 프로젝트 의사결정 기록

## 2026-07-27 — 시장가 수집·증빙과 표시 방식 확정

- 시장가 출처는 `DeviceMart`와 `Mouser Korea` 두 곳으로 확정한다.
- 전체 상품 카탈로그를 복제하지 않는다. 회사에서 비교할 가능성이 높은
  품목과 검토된 검색 목록을 사전 수집하고, 신규 견적의 내부 표준 DB
  미매칭 품목은 실시간 조회 후 시장가 DB에 축적한다.
- 조회 순서는 `내부 표준 DB → 유효한 시장가 캐시 → 미보유·만료 시 외부
  조회`다. 기본 시장가 유효기간은 7일이며 출처별로 조정할 수 있다.
- Mouser는 공식 Search API를 사용하고 DeviceMart는 공개 검색·상품
  상세페이지 수집 어댑터를 사용한다.
- 시장가와 내부 표준단가는 서로 다른 근거로 저장하며 자동으로 합치지 않는다.
- 시장가 결과에는 출처, 상품명, 제조사·모델, 수량 구간별 단가, 재고,
  최소 주문수량, 수집 시각과 유효기간을 표시한다.
- 상품 사진, 원본 상품 링크와 함께 수집 당시 API 응답 또는 HTML,
  페이지 캡처 이미지와 해시를 증빙으로 보존한다.
- 화면에서는 신규 견적 품목별로 제시 단가, 시장가 범위, 판정과
  출처·사진·원본 링크를 나란히 확인할 수 있게 한다.
- 발표 시 사용할 설명은 `docs/PRESENTATION_MARKET_PRICE.md`를 기준으로 한다.

## 2026-07-25 — 데이터 정제·그룹핑·시장가 설계 승인

- `docs/superpowers/specs/2026-07-25-data-cleansing-grouping-market-price-design.md`를 구현 기준으로 승인했다.
- 구현은 다음 세 단계로 진행한다.
  1. 로컬 FastAPI·SQLite 기반 원본/정제 데이터 계층
  2. 표준품목 그룹핑·hChat 임베딩·표준단가 버전 이력
  3. DeviceMart·Mouser 시장가 캐시·증빙·검토 화면
- 초기 실행 환경은 로컬이며 사내 서버 설치와 조직 인증은 이후 단계로 남긴다.
- 보호 원본은 삭제하지 않고 `_보안해제.xlsx`를 분석 우선본으로 사용한다.

## 2026-07-24 — 표준단가 DB의 출처와 보안 파일 처리

### 표준단가 DB 정의

- `표준단가DB`는 회사가 협력사 등으로부터 실제로 받은 **과거 견적서**를 정제·집계해 구축한 내부 견적 이력 DB다.
- 따라서 표준단가는 외부 시장가격이나 공개 사이트의 판매가격을 의미하지 않는다.
- 외부 API·가격 비교 사이트·크롤링으로 수집한 가격은 `외부 시장가`로 별도 저장한다.
- 가격 검토 시 내부 DB에서 동일·유사 품목이 검색되면 과거 견적 단가를 우선 비교 근거로 사용한다.
- 내부 DB에 신뢰할 만한 매칭이 없을 때만 외부 시장가를 보조 근거로 조회한다.

### 보안 파일 처리 — 2026-07-25 업데이트

- 로컬 저장소의 원본 중 DRM/IRM 보호가 남아 분석할 수 없던 파일은 총 **12개**였다.
- 사용자가 각 파일을 Excel 회사 계정으로 열고 파일명 뒤에 `_보안해제`를 붙인 `.xlsx` 복사본으로 저장했다.
- 12개 보안해제본을 실제 워크북으로 불러와 전체 시트의 사용 범위와 셀 값을 검사했다.
- 12개 모두 열기와 데이터 조회에 성공했고, `IRM protected`, `DRMTransform` 등 보호 문구가 남아 있지 않았다.
- 기존 2020년 `_보안해제.xlsx` 3개까지 포함하면 현재 확인된 보안해제본은 총 15개이며 모두 분석 가능하다.
- 보호 원본은 증빙으로 그대로 보관하고, 파싱 시 동일 논리 문서의 `_보안해제.xlsx`를 우선 선택한다.
- 원본과 보안해제본을 별도 견적으로 중복 적재하지 않는다.
- 현재 보안해제본 12개는 Git 미추적 파일이므로 커밋·푸시 전에 명시적으로 포함해야 한다.

### 근거 데이터 분리 원칙

| 구분 | 의미 | 가격 검토에서의 역할 |
|---|---|---|
| 내부 과거 견적 | 회사가 실제로 받은 견적서의 품목·규격·단가 | 표준단가와 유사 견적 비교의 주 근거 |
| 외부 시장가 | 외부 API·웹사이트·크롤링·수동 조사 가격 | 내부 매칭이 없거나 약할 때 사용하는 보조 근거 |
| 신규 검토 결과 | 담당자가 최종 검토·승인한 신규 견적 가격 | 승인 후 표준단가 갱신 후보 |

## 2026-07-24 — 표준단가 지정 정책 및 임베딩 API

### 표준단가 지정 정책

- 근거 견적 건수와 무관하게 **모든 집계 품목을 표준단가로 지정**한다.
- DB 데이터 절대량이 적으므로 1건짜리 집계도 표준단가로 취급한다.
- `후보단가` 분리 없음 — `status` 필드 추가 불필요.
- 향후 데이터 축적 후 재검토 가능.

### 임베딩 API

- 외부 `sentence-transformers + FAISS` 구성 **취소**.
- 사내 **hChat API (OpenAI 호환)** 사용 확정.
- 실제 모델명과 요청·응답 형식은 사내 API 샘플을 받은 뒤 확정한다.
- 현재 환경변수 자리는 `HCHAT_EMBEDDING_ENABLED`,
  `HCHAT_EMBEDDING_ENDPOINT`, `HCHAT_EMBEDDING_API_KEY`,
  `HCHAT_EMBEDDING_MODEL`, `HCHAT_EMBEDDING_API_STYLE`이다.
- 로컬 기본값은 비활성화다. API 키는 사용자가 사내망에서 별도 주입하며
  로그·보고서·Git에 기록하지 않는다.

## 2026-07-27 — 표준 DB 자동 구축과 신규 견적 분석

- 기존 `표준단가DB.xlsx`는 초창기 수작업 산출물이다. 현재 시스템의 입력,
  검증, 비교, 내보내기, 증빙으로 사용하지 않는다.
- 표준 DB는 최신 문서 역할이 `HISTORICAL_REFERENCE`인 과거 견적서의 최신
  `INCLUDED` 원본 행만으로 구축한다. 신규 접수 문서인 `INCOMING_BID`는
  어떤 경우에도 표준 DB 입력에 섞지 않는다.
- 그룹 키는 정규화한 `품명 + 사양 + 단위`의 완전 일치다. 단위가 다르면
  별도 그룹이며, 품명이 비었거나 단위 충돌이 있으면 자동 확정하지 않는다.
- 근거가 1건인 그룹도 표준단가로 사용할 수 있지만 화면에 `근거 1건`
  경고와 원본 증빙을 함께 표시한다.
- `standard-db-build`는 입력 fingerprint와 규칙 버전으로 멱등 실행한다.
  동일 입력 재실행은 기존 성공 실행을 재사용하고 새 표준품목·멤버십·가격을
  만들지 않는다.
- 표준품목, 소속 결정, 가격 버전은 현재 상태만 조회하되 이력은 append-only로
  보존한다. 정정은 기존 행을 삭제·수정하지 않고 새 결정을 추가한다.
  기존 수동 소속과 충돌하면 자동 구축 전체를 롤백하고 사람이 검토한다.
- 신규 견적서는 웹 `/analysis`에서 업로드한다. 분석은 업로드 당시의 최신
  정제 결정과 표준가격을 읽기 전용으로 사용하며, 자동 멤버십이나 표준가격을
  생성하지 않는다. 완전 일치하지 않는 후보는 설비구매팀 검토 대상으로 둔다.
- `판정대기` 항목은 자동 포함·삭제하지 않고 설비구매팀이 추후 검토한다.
- Excel 내보내기 기능은 만들지 않는다. 업무 흐름은 웹 업로드와 웹 분석이다.
- DeviceMart·Mouser는 시장가를 미리 수집한 별도 DB를 우선 사용하고 없는
  품목만 실시간 조회하는 후속 단계다. URL, 조회 시각, 이미지 등 원본 증빙을
  보존한다.
- hChat 임베딩은 환경변수 기반 어댑터 자리만 유지하며 사내망에서 API 샘플과
  키를 받은 뒤 시험한다. 로컬에서는 호출하지 않는다.
- 서버 설치와 조직 인증은 로컬 검증 완료 뒤 별도 단계로 진행한다.
