# 프로젝트 의사결정 기록

## 2026-08-11 — 원본 근거형 문서 메타데이터와 팀 엑셀 사용 범위

- 팀 최신 `표준단가DB.xlsx`는 데이터 품질 문제 확인용 참고자료이며 운영값,
  재구축 입력, 검증 정답으로 사용하지 않는다.
- `바츠추출`, `AONE협력사`는 공급사가 아니라 수집 경로로 저장한다.
- 공급사·견적일·공사명은 원본 문서의 명시된 라벨과 시트·셀 또는 PDF
  페이지가 확인된 필드만 자동 반영한다.
- 원본에서 확인되지 않는 값은 추정하지 않는다. 원본 공란과 파서 누락도
  별도 상태로 관리한다.
- 운영 DB 교체는 신규 견적 접수 이력까지 보존되는 경우에만 수행한다.
  독립 재구축 결과는 검증용으로 유지한다.

## 2026-08-11 — 미활용 원본 회수와 자동 포함 안전 기준

- PDF 분리·부분 헤더, 좌표형 표, 레거시 숫자행, 외국어·번체 헤더와 ZIP
  내부 Excel을 지원한다.
- OCR로 추출한 모든 행은 원본 확인 전 `REVIEW_REQUIRED`로 유지한다.
- 여러 번호 품목이 한 셀에 합쳐진 행, 합계·VAT, 역산 단가, 규격 열을
  확정할 수 없는 PDF 행은 자동 표준가격에 포함하지 않는다.
- 구형 XLS 복구본은 원본과 분리해 `견적서/복구본/3차 학습/`에 보존한다.
- 운영 DB 갱신은 운영 DB 복사본에서 오탐·신규견적 이력·SQLite 무결성을
  확인한 뒤 승격한다. 갱신 명령은 실행 전 백업을 자동 생성한다.
- 사내 보안 파일은 원본을 덮어쓰지 않고 `_보안해제` 정상본을 추가한 뒤
  증분 적재한다.

## 2026-07-27 — 시장가 수집·증빙과 표시 방식 확정

- 시장가 출처는 `DeviceMart`와 `Mouser Korea` 두 곳으로 확정한다.
- 전체 상품 카탈로그를 복제하지 않는다. 회사에서 비교할 가능성이 높은
  품목과 검토된 검색 목록을 사전 수집하고, 신규 견적의 내부 표준 DB
  미매칭 품목은 실시간 조회 후 시장가 DB에 축적한다.
- 조회 순서는 `내부 표준 DB → 유효한 시장가 캐시 → 미보유·만료 시 외부
  조회`다. 기본 시장가 유효기간은 7일이며 출처별로 조정할 수 있다.
- Mouser는 공식 Search API를 사용하고 DeviceMart는 공개 검색·상품
  상세페이지 수집 어댑터를 사용한다.
- 시장가와 내부 표준단가는 서로 다른 근거로 저장하며 자동으로 합치지 않는다.
- 시장가 결과에는 출처, 상품명, 제조사·모델, 수량 구간별 단가, 재고,
  최소 주문수량, 수집 시각과 유효기간을 표시한다.
- 상품 사진, 원본 상품 링크와 함께 수집 당시 API 응답 또는 HTML,
  페이지 캡처 이미지와 해시를 증빙으로 보존한다.
- 화면에서는 신규 견적 품목별로 제시 단가, 시장가 범위, 판정과
  출처·사진·원본 링크를 나란히 확인할 수 있게 한다.
- 발표 시 사용할 설명은 `docs/PRESENTATION_MARKET_PRICE.md`를 기준으로 한다.

## 2026-07-25 — 데이터 정제·그룹핑·시장가 설계 승인

- `docs/superpowers/specs/2026-07-25-data-cleansing-grouping-market-price-design.md`를 구현 기준으로 승인했다.
- 구현은 다음 세 단계로 진행한다.
  1. 로컬 FastAPI·SQLite 기반 원본/정제 데이터 계층
  2. 표준품목 그룹핑·hChat 임베딩·표준단가 버전 이력
  3. DeviceMart·Mouser 시장가 캐시·증빙·검토 화면
- 초기 실행 환경은 로컬이며 사내 서버 설치와 조직 인증은 이후 단계로 남긴다.
- 보호 원본은 삭제하지 않고 `_보안해제.xlsx`를 분석 우선본으로 사용한다.

## 2026-07-24 — 표준단가 DB의 출처와 보안 파일 처리

### 표준단가 DB 정의

- `표준단가DB`는 회사가 협력사 등으로부터 실제로 받은 **과거 견적서**를 정제·집계해 구축한 내부 견적 이력 DB다.
- 따라서 표준단가는 외부 시장가격이나 공개 사이트의 판매가격을 의미하지 않는다.
- 외부 API·가격 비교 사이트·크롤링으로 수집한 가격은 `외부 시장가`로 별도 저장한다.
- 가격 검토 시 내부 DB에서 동일·유사 품목이 검색되면 과거 견적 단가를 우선 비교 근거로 사용한다.
- 내부 DB에 신뢰할 만한 매칭이 없을 때만 외부 시장가를 보조 근거로 조회한다.

### 보안 파일 처리 — 2026-07-25 업데이트

- 로컬 저장소의 원본 중 DRM/IRM 보호가 남아 분석할 수 없던 파일은 총 **12개**였다.
- 사용자가 각 파일을 Excel 회사 계정으로 열고 파일명 뒤에 `_보안해제`를 붙인 `.xlsx` 복사본으로 저장했다.
- 12개 보안해제본을 실제 워크북으로 불러와 전체 시트의 사용 범위와 셀 값을 검사했다.
- 12개 모두 열기와 데이터 조회에 성공했고, `IRM protected`, `DRMTransform` 등 보호 문구가 남아 있지 않았다.
- 기존 2020년 `_보안해제.xlsx` 3개까지 포함하면 현재 확인된 보안해제본은 총 15개이며 모두 분석 가능하다.
- 보호 원본은 증빙으로 그대로 보관하고, 파싱 시 동일 논리 문서의 `_보안해제.xlsx`를 우선 선택한다.
- 원본과 보안해제본을 별도 견적으로 중복 적재하지 않는다.
- 현재 보안해제본 12개는 Git 미추적 파일이므로 커밋·푸시 전에 명시적으로 포함해야 한다.

### 근거 데이터 분리 원칙

| 구분 | 의미 | 가격 검토에서의 역할 |
|---|---|---|
| 내부 과거 견적 | 회사가 실제로 받은 견적서의 품목·규격·단가 | 표준단가와 유사 견적 비교의 주 근거 |
| 외부 시장가 | 외부 API·웹사이트·크롤링·수동 조사 가격 | 내부 매칭이 없거나 약할 때 사용하는 보조 근거 |
| 신규 검토 결과 | 담당자가 최종 검토·승인한 신규 견적 가격 | 승인 후 표준단가 갱신 후보 |

## 2026-07-24 — 표준단가 지정 정책 및 임베딩 API

### 표준단가 지정 정책

- 근거 견적 건수와 무관하게 **모든 집계 품목을 표준단가로 지정**한다.
- DB 데이터 절대량이 적으므로 1건짜리 집계도 표준단가로 취급한다.
- `후보단가` 분리 없음 — `status` 필드 추가 불필요.
- 향후 데이터 축적 후 재검토 가능.

### 임베딩 API

- 외부 `sentence-transformers + FAISS` 구성 **취소**.
- 사내 **hChat API (OpenAI 호환)** 사용 확정.
- 실제 모델명과 요청·응답 형식은 사내 API 샘플을 받은 뒤 확정한다.
- 현재 환경변수 자리는 `HCHAT_EMBEDDING_ENABLED`,
  `HCHAT_EMBEDDING_ENDPOINT`, `HCHAT_EMBEDDING_API_KEY`,
  `HCHAT_EMBEDDING_MODEL`, `HCHAT_EMBEDDING_API_STYLE`이다.
- 로컬 기본값은 비활성화다. API 키는 사용자가 사내망에서 별도 주입하며
  로그·보고서·Git에 기록하지 않는다.

## 2026-07-27 — 표준 DB 자동 구축과 신규 견적 분석

- 기존 `표준단가DB.xlsx`는 초창기 수작업 산출물이다. 현재 시스템의 입력,
  검증, 비교, 내보내기, 증빙으로 사용하지 않는다.
- 표준 DB는 최신 문서 역할이 `HISTORICAL_REFERENCE`인 과거 견적서의 최신
  `INCLUDED` 원본 행만으로 구축한다. 신규 접수 문서인 `INCOMING_BID`는
  어떤 경우에도 표준 DB 입력에 섞지 않는다.
- 그룹 키는 정규화한 `품명 + 사양 + 단위`의 완전 일치다. 단위가 다르면
  별도 그룹이며, 품명이 비었거나 단위 충돌이 있으면 자동 확정하지 않는다.
- 근거가 1건인 그룹도 표준단가로 사용할 수 있지만 화면에 `근거 1건`
  경고와 원본 증빙을 함께 표시한다.
- `standard-db-build`는 입력 fingerprint와 규칙 버전으로 멱등 실행한다.
  동일 입력 재실행은 기존 성공 실행을 재사용하고 새 표준품목·멤버십·가격을
  만들지 않는다.
- 표준품목, 소속 결정, 가격 버전은 현재 상태만 조회하되 이력은 append-only로
  보존한다. 정정은 기존 행을 삭제·수정하지 않고 새 결정을 추가한다.
  기존 수동 소속과 충돌하면 자동 구축 전체를 롤백하고 사람이 검토한다.
- 신규 견적서는 웹 `/analysis`에서 업로드한다. 분석은 업로드 당시의 최신
  정제 결정과 표준가격을 읽기 전용으로 사용하며, 자동 멤버십이나 표준가격을
  생성하지 않는다. 완전 일치하지 않는 후보는 설비구매팀 검토 대상으로 둔다.
- `판정대기` 항목은 자동 포함·삭제하지 않고 설비구매팀이 추후 검토한다.
- Excel 내보내기 기능은 만들지 않는다. 업무 흐름은 웹 업로드와 웹 분석이다.
- DeviceMart·Mouser는 시장가를 미리 수집한 별도 DB를 우선 사용하고 없는
  품목만 실시간 조회하는 후속 단계다. URL, 조회 시각, 이미지 등 원본 증빙을
  보존한다.
- hChat 임베딩은 환경변수 기반 어댑터 자리만 유지하며 사내망에서 API 샘플과
  키를 받은 뒤 시험한다. 로컬에서는 호출하지 않는다.
- 서버 설치와 조직 인증은 로컬 검증 완료 뒤 별도 단계로 진행한다.

## 2026-08-11 — 팀 엑셀 견적일은 출처파일 대조로만 보완

- 팀 엑셀의 가격 집계와 K열 최근 견적일을 그대로 이관하지 않는다.
- K열은 문자열 최댓값으로 생성돼 실제 날짜가 있어도 `미확인`이 선택되는
  오류가 확인됐다.
- 동일 원본임을 이용해 원본 시트 D열의 견적일과 동반 JSON `출처파일`을
  현재 원본 파일에 일대일로 연결한다.
- `미확인`과 임시값 `2025-01-01`은 제외하고, 이미 원본에서 확인한 날짜는
  충돌하더라도 덮어쓰지 않는다.
- 바츠 파일명 앞자리에서 얻은 날짜는 `FILE_DATE_INFERRED`로 저장하고
  연도 기준 저신뢰 근거로 표시한다. 1·2차 기존 정리값은
  `REFERENCE_BACKFILL`, 원본 확인값은 `CONFIRMED`로 구분한다.
- 메타데이터와 표준가격 관측 이력은 append-only로 갱신하며 같은 자료의
  재실행은 새 버전을 중복 생성하지 않는다.

## 2026-08-11 — 견적서 본문·머리말 날짜를 최우선 근거로 사용

- DB에 등록된 모든 과거 견적의 표지·머리말과 본문을 다시 확인한다.
- `견적일`, `제출일`, `작성일`, `발행일`, 영문 `DATE`처럼 명시된 날짜를
  최우선으로 사용한다. 표지의 날짜와 상세 페이지 작성일이 다르면 표지의
  견적 날짜를 선택하고 상세 날짜는 검토 이력으로 남긴다.
- 견적번호에 포함된 숫자, 납기일, 유효기간, 결제일은 기준 날짜로 사용하지
  않는다. 파일명 날짜나 팀 엑셀 날짜보다 원본에 적힌 날짜가 우선한다.
- 텍스트가 없는 PDF는 로컬 OCR로 표지 2쪽까지만 확인한다. OCR 날짜도
  견적서 표지에서 단일 날짜로 확인되는 경우에만 반영하며 출처 페이지와
  문맥을 증빙에 기록한다.
- 원본에서 날짜를 찾지 못한 문서는 억지로 추정하지 않고 날짜 미확인으로
  유지한다. 물가 보정용 기준일은 근거가 확보된 문서에만 적용한다.

## 2026-08-11 — 신규 견적 분석을 가격 적정성과 구매 목표가로 분리

- 신규 견적은 한 번만 접수하고 결과 화면에서 `가격 적정성`과
  `구매 목표가` 두 탭으로 확인한다.
- 가격 적정성 임계값은 분석 실행별로 저장한다. 기본값은 적정 `±10%`,
  고가·저가 `±20%`이며 실행 이력의 값을 나중에 변경하지 않는다.
- 구매 목표가는 한국은행 생산자물가지수 총지수(KOSIS 기관 `301`, 통계표
  `DT_404Y014`, 항목 `13103134604999`, 총지수 분류
  `13102134604ACC_CD.*AA`, 월별, `2020=100`)를 사용한다.
- 과거 단가별로 `원본 단가 × 목표월 지수 ÷ 원본 견적월 지수`를 계산한 뒤
  보정 단가의 중앙값을 구매 목표 단가로 사용한다. 별도 협상 할인율은
  적용하지 않는다.
- 날짜는 메타데이터 증빙이 `SOURCE_CONFIRMED`이고 물가지수 사용 상태가
  `EXACT_DATE`인 원본 본문·머리말 확인값만 사용한다. 팀 엑셀 보완값
  (`REFERENCE_BACKFILL`)과 파일명 추정값(`FILE_DATE_INFERRED`)은 제외한다.
- 표준 DB에 없는 품목의 DeviceMart·Mouser 시장가는 별도 근거다. 시장가를
  물가보정 관측값에 섞거나 임의 목표가로 만들지 않는다.
- KOSIS는 갱신 작업에서만 호출한다. 분석은 DB에 저장된 마지막 정상
  스냅숏을 사용하며, 실행 당시 지수·산식·원본 근거를 append-only로 보존한다.

## 2026-08-12 — 표준 DB 운영 투영과 소비자물가 목표가

- 2026-08-11의 생산자물가지수 기반 신규 목표가 정책은 과거 실행 재현용으로만
  보존한다. 2026-08-12 이후 생성하는 분석 실행에는 생산자물가지수를 사용하지
  않는다.
- 신규 구매 목표가는 KOSIS 소비자물가 등락률의 `총지수`만 사용한다. 고정
  식별자는 기관 `101`, 통계표 `DT_1J22041`, 항목 `T`, 분류 `0`, 주기
  `연간`, 단위 `%`다.
- 과거 개당 단가는 `견적연도+1`부터 마지막 확정연도까지의 연간 등락률을
  `∏(1 + 등락률/100)`으로 복리 적용한다. 보정된 근거 단가들의 중앙값을
  구매 목표 단가로 사용하며 최종 단가와 금액만 원 단위로 반올림한다.
- 필요한 연간 값이 하나라도 없으면 `연간 소비자물가 자료 누락`으로 남기고
  다른 지수로 대체하지 않는다. 2026년 연간 값이 확정되기 전에는 2025년
  확정 소비자물가 기준이라고 표시한다.
- 표준가격 운영 조회는 현재 입력·계산식·코드 지문이 모두 일치하는 성공
  빌드의 투영 결과만 사용한다. 일치하는 빌드가 없으면 마지막 가격을 자동
  적용하지 않고 `재구축 필요`로 표시한다.
- 동일한 복사 원본은 삭제하지 않고 하나의 대표 근거로 계산한다. 대표는
  원본에서 확인된 최신 견적일, 명시된 최신 개정번호, 정상 파싱 원본,
  최근 수집본 순으로 선택하며 모든 중복 raw ID는 감사 이력으로 연결한다.
- 값이 다른 자료는 명시적인 동일 개정 계열이 확인된 경우에만 최신 개정본을
  대표로 선택한다. 개정 관계가 불명확하면 별도 가격 관측으로 유지한다.
- 신규 견적의 가격 근거 선택 순서는 `활성 표준 DB → 유효한 시장가 캐시 →
  DeviceMart·Mouser 실시간 조회 → 판정 대기`다. 제조사·정확한 모델번호,
  수량·MOQ·재고가 확인된 시장가만 자동 판정에 사용하고 유사 상품은 참고
  링크로만 표시한다.

## 2026-08-13 — 구매 목표가는 보정된 과거 실구매 최저가로 산정

- 가격 적정성의 중립 기준은 기존대로 표준 DB 중앙값과 범위를 사용한다.
- 구매 목표가는 원본 날짜가 확인된 과거 실구매 단가를 마지막 확정연도
  소비자물가로 각각 보정한 뒤 가장 낮은 단가를 채택한다. 이는 평균적인 적정가가
  아니라 구매팀이 협상에서 우선 제시할 공격적인 목표다. 이 정책은 2026-08-12의
  보정 단가 중앙값 정책을 대체한다.
- 목표가가 산정된 품목의 견적금액만 목표금액과 비교해 절감 여지를 계산한다.
  목표가가 없는 품목을 견적 총액에 포함해 절감액을 과장하지 않는다.
- 구매 목표가 화면에는 별도의 물가보정 기준가격을 함께 표시하지 않는다.
  적용 연도와 공식 통계, 원본별 계산 과정은 `산정 방식`과 `산정 근거`를 열었을
  때만 제공한다. 중앙값과 가격 범위는 가격 적정성 화면에서 확인한다.

## 2026-08-12 정제 재평가 원칙

- 파서가 바뀌면 원본 행을 덮어쓰지 않고 새 `source_parse_run/output`을 추가한다.
  운영 조회는 원본별 최신 성공 파싱 실행만 사용한다.
- 엑셀 부동소수점 꼬리는 6자리 저장 정밀도에서만 보정하며, 실제 열 결합이나 숫자
  중복으로 보이는 값은 자동 수정하지 않는다.
- 수량 0·금액 0이면서 개당 단가가 유효한 행은 정상 관측으로 사용할 수 있다.
- 금액 검산은 원본 수식에 명시된 일수·인원·수량 등 모든 곱셈 인수를 사용한다.
  교차 시트나 복합 합계는 단순 금액 불일치로 단정하지 않는다.
- 제조사 복구 성공은 검토 사유가 아니라 출처 이력이다. 실제 검토 사유와 분리한다.
- OCR·특수 PDF는 헤더, 중요 숫자, 개당 단가와 계산 일치가 함께 확인된 고신뢰
  결과만 자동 반영한다. 나머지는 추출 실패 유형을 명시하고 검토 대상으로 유지한다.
- 단가 편차 판정은 비교 관측값과 원본 위치가 저장된 경우에만 유효하다. 기존 근거 없는
  판정은 `outlier-mad-v2` 증빙으로 교체한다.
