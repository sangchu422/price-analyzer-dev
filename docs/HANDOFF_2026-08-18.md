## 구매 판단과 협상 목표의 현재 원칙

### 가격 적정성

- 과거 견적의 최저·중앙값·최고값을 함께 보여준다.
- 기본 임계치는 중앙값 대비 `±10% 적정`, `±10~20% 주의`, `±20% 초과 고가·저가`다.
- 규격이 비어 있고 가격 범위가 2배를 넘는 그룹은 자동 판정하지 않는다.
- 표준 DB가 없을 때만 시장가를 확인하며, 정확한 모델번호가 없는 제작품·가공품은 외부
  유사 상품을 자동 근거로 사용하지 않는다.

### 구매 목표가와 네고 가능금액

- 원본 견적일이 확인된 독립 원본의 과거 개당 단가를 KOSIS 소비자물가 총지수 등락률로
  현재 가치에 보정한다.
- 같은 문서의 복사본은 한 번만 계산하고, 보정된 단가 중 최저값을 협상 목표 단가로 사용한다.
- 품목별 네고 가능금액은 현재 구매금액이 목표금액보다 높은 경우만 합산한다.
- 이미 목표가보다 싸게 들어온 품목은 네고 가능금액 `0원`으로 두며 다른 품목의 여력을
  상쇄하지 않는다.
- 전체 협상 목표금액은 `전체 견적금액 - 네고 가능금액`이다.
- 근거가 부족한 품목은 현재 구매금액을 유지하며 목표가를 만들어내지 않는다.

## 데이터 갱신 순서

원본 견적이 바뀌거나 파싱·정제 규칙을 갱신한 경우 저장소 루트에서 다음 명령을 사용한다.

```bat
scripts\start-local.bat --refresh-data
```

이 옵션은 원본 증분 적재 후 최신 정제 규칙으로 전수 재평가하고 표준 DB를 다시 만든다.
운영 DB를 직접 덮어쓰기 전에 반드시 `backend/.local/backups/`에 복사본을 남긴다.

수동으로 확인할 때는 다음 순서다.

```bat
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m app.cli ingest --quote-root ..\견적서 --database-file .local\standard-item-migration-v2.sqlite3 --report .local\reports\latest-ingestion.json --json
..\.venv\Scripts\python.exe -m app.cleansing.reassess
..\.venv\Scripts\python.exe -m app.cli standard-db-build --database-file .local\standard-item-migration-v2.sqlite3 --report .local\reports\latest-standard-db.json --json --actor local-operator
```

같은 원본과 같은 규칙으로 재실행했을 때 새 파싱 행·판정·표준가격이 중복 생성되지 않는지
확인한다.
