# 기존 견적 기반 자동 표준 DB 구축 설계

## 1. 목적

회사가 보유한 과거 견적서의 정제된 품목 행으로 내부 표준 DB를 자동
구축한다. 신규 입찰 견적서는 웹에서 별도로 첨부하며, 표준 DB와 비교해
품목별·견적서 전체 가격 적정성을 평가한다.

기존 `표준단가DB.xlsx`는 초창기 수작업 산출물이므로 입력, 대조, 검증,
승계, 내보내기 또는 운영 근거로 사용하지 않는다.

## 2. 확정 원칙

- 표준 DB의 유일한 입력은 과거 견적 원본에서 파싱한 현재 최신
  `INCLUDED` 행이다.
- 품명·사양·단위의 정규화 키가 같은 행은 동일 표준품목으로 자동
  그룹핑한다.
- 근거가 1건뿐인 품목도 표준 DB에 포함하고 `근거 1건`으로 표시한다.
- 의미가 비슷하다는 이유만으로 가격 근거를 자동 합치지 않는다.
  임베딩은 추후 유사 품목 후보 탐색에만 사용한다.
- 원본 견적서, 시트·행 또는 PDF 페이지까지 모든 가격 근거를 역추적할
  수 있어야 한다.
- 같은 입력과 같은 규칙으로 재실행하면 표준품목, 소속 결정, 가격
  버전을 중복 생성하지 않는다.
- 신규 견적서는 표준 DB 구축 입력에 자동으로 포함하지 않는다.

## 3. 문서 역할 분리

견적 문서는 다음 두 역할로 분리한다.

### `HISTORICAL_REFERENCE`

기존 입찰에서 회사가 받은 과거 견적서다. 정제가 완료된 `INCLUDED` 행은
표준 DB 구축 입력이 된다. 현재 로컬 DB에 적재된 기존 견적 문서는 최초
구축 시 이 역할로 분류한다.

### `INCOMING_BID`

웹에서 새로 첨부하는 검토 대상 견적서다. 표준 DB와 비교하는 데만
사용하며 표준가격 계산에는 포함하지 않는다. 추후 설비구매팀이 확정한
견적을 과거 근거로 편입하는 절차는 별도 승인 기능으로 다룬다.

문서 역할은 가격 계산 시 반드시 검사한다. 이 구분으로 새 견적이 자기
자신의 비교 기준에 섞이는 데이터 누수를 방지한다.

## 4. 자동 표준 DB 구축

### 입력 선택

각 과거 견적 행의 최신 정제 결정만 조회한다.

- `INCLUDED`: 구축 대상
- `EXCLUDED`: 제외
- `REVIEW_REQUIRED`: 설비구매팀 검토 전까지 제외
- 품명 정규화값 결측: 제외하고 구축 보고서에 기록

수량·단가·금액 중 가격 계산에 필요한 단가가 없거나 숫자가 아니면
표준품목 그룹에는 포함할 수 있지만 표준가격 관측값에서는 제외한다.

### 그룹 키

자동 그룹 키는 다음 세 값의 정규화 결과다.

1. 품명
2. 사양
3. 단위

공백, 대소문자, 전각·반각과 확정된 정규화 사전은 동일하게 처리한다.
같은 품명·사양이라도 단위가 다르면 서로 다른 표준품목으로 유지하고
단위 충돌을 구축 보고서에 표시한다.

의미 유사도, 임베딩 점수, 제조사 유사성만으로는 자동 병합하지 않는다.
잘못된 병합은 서로 다른 가격을 하나의 기준으로 만드는 위험이 있기
때문이다.

### 안정적인 표준품목과 버전

기존 `StandardItem`, `StandardItemVersion`,
`ItemMembershipDecision`, `StandardPriceVersion` 구조를 표준 DB의
운영 계층으로 사용한다.

- 같은 정규화 키의 기존 표준품목이 있으면 내부 ID를 유지한다.
- 신규 키만 새 표준품목을 생성한다.
- 구성원 변화는 기존 결정을 수정하지 않고 새 소속 결정으로 기록한다.
- 현재 입력 지문과 계산 결과가 기존 버전과 같으면 새 버전을 만들지
  않는다.
- 구성원이나 집계 결과가 달라졌을 때만 새 표준단가 버전을 만든다.
- 제거된 과거 행도 이력에서 삭제하지 않고 최신 결정으로 비활성화한다.

자동 구축은 사람의 기존 수동 그룹 결정을 덮어쓰지 않는다. 수동 결정과
자동 키가 충돌하면 해당 그룹을 구축 실패로 격리하고 보고한다.

### 가격 집계

현재 유효한 과거 견적 근거만 사용해 다음 값을 계산한다.

- 최소 단가
- 중앙값 단가
- 평균 단가
- 최대 단가
- 가격 근거 수
- 공급업체 수와 공급업체 목록
- 주요 제조사
- 최근 견적일

근거 1건도 정상 표준가격으로 저장하지만 API와 화면에서
`SINGLE_OBSERVATION`을 명시한다. 두 건 이상은
`MULTI_OBSERVATION`으로 표시한다.

### 구축 실행 기록

`standard_database_build_run`에 다음을 저장한다.

- 규칙·정규화·계산 버전
- 대상 과거 문서와 최신 정제 결정의 입력 지문
- 시작·완료 시각과 상태
- 대상·포함·제외·검토대기 행 수
- 생성·재사용·변경된 표준품목 수
- 생성·재사용된 가격 버전 수
- 품명 결측, 단위 충돌, 수동 결정 충돌, 가격 결측 수
- JSON 구축 보고서 경로

전체 실행은 하나의 트랜잭션으로 처리한다. 일부 그룹 처리에 실패하면
표준품목·소속·가격 변경을 전부 롤백하고 실패 보고서만 남긴다.

## 5. 실행 방식

초기 구축과 재구축은 명시적인 로컬 백엔드 명령으로 실행한다.

```powershell
python -m app.cli standard-db-build `
  --database-file backend/.local/standard-item-migration-v2.sqlite3
```

애플리케이션 시작 시 자동 재구축하지 않는다. 시작 지연과 예기치 않은
가격 기준 변경을 방지하기 위해 다음 경우에만 실행한다.

- 과거 견적 원본을 새로 수집·정제한 뒤
- 정제 또는 수동 그룹 결정이 변경된 뒤
- 정규화·가격 계산 규칙 버전을 올린 뒤

같은 입력 지문으로 재실행하면 기존 성공 실행을 반환하고 쓰기 작업을
하지 않는다.

## 6. 웹 흐름

### 제거 대상

- `/reconciliation` 페이지와 내비게이션
- 기존 엑셀 업로드·대조·행 결정·승계·승인 API
- 레거시 STD 코드와 엑셀 집계 비교 표시
- 기존 엑셀 증빙 보존 기능
- 엑셀 내보내기 기능

### 표준 DB 조회

`/standard-prices`는 자동 구축된 내부 표준 DB를 조회하는 화면으로
정리한다.

- 표준품목 검색
- 품명·사양·단위
- 최소·중앙·평균·최대 단가
- 근거 수와 `근거 1건` 경고
- 공급업체·제조사·최근 견적일
- 원본 견적 근거 링크
- 표준가격 버전 이력
- 마지막 구축 시각과 규칙 버전

자동 구축 결과를 화면에서 다시 승인하는 단계는 두지 않는다.

### 신규 견적 분석

`/analysis`에서 사용자가 신규 견적 파일을 첨부한다.

1. 파일을 `INCOMING_BID`로 보존하고 파싱한다.
2. 정제 결과를 확정하거나 판정대기 행을 표시한다.
3. 각 품목을 내부 표준품목과 매칭한다.
4. 최근 성공한 자동 구축에서 생성된 최신 표준가격 버전과 신규 단가를
   비교한다.
5. 표준 DB에 신뢰 가능한 매칭이 없으면 시장가 DB 조회 대상으로
   표시한다.
6. 품목별 `저가`, `적정`, `검토`, `고가`와 차이 금액·비율을 표시한다.
7. 판정 가능한 품목의 금액 비중을 반영해 견적서 전체 적정성을
   요약한다.

현재 단계에서는 DeviceMart·Mouser 시장가 수집과 hChat 실연결을
구현하지 않는다. 해당 품목은 후속 연동 대상으로 명확히 표시한다.

## 7. 잘못 구현된 레거시 대조 기능 정리

현재 작업 브랜치에 아직 커밋되지 않은 레거시 대조 구현은 폐기한다.

- `LegacyReconciliationPage`와 관련 클라이언트 타입·스타일 제거
- `app/reconciliation`, 대조 API와 레거시 모델 제거
- 레거시 용도의 Alembic `0007`을 자동 표준 DB 구축 실행 구조로 교체
- 로컬 DRAFT 대조 실행과 레거시 증빙 복사본 제거
- 표준가격·분석 응답의 `legacy_codes`,
  `reconciliation_run_id`, `legacy_comparison` 제거
- 의사결정·인수인계 문서의 대조·승계 설명을 본 설계로 교체

실제 로컬 DB는 적용 전 백업에서 복원하거나 빈 레거시 테이블을
downgrade한 뒤 새 `0007`을 적용한다. 표준가격 승인이나 외부코드가
생성되지 않았음을 확인한 뒤 수행한다.

## 8. 오류 처리와 안전장치

- 과거 문서와 신규 견적의 역할이 없거나 모호하면 가격 계산을 거부한다.
- 정제 결정이 최신이 아니면 해당 행을 사용하지 않는다.
- 단위가 다르면 같은 가격 그룹으로 합치지 않는다.
- 수동 그룹 결정 충돌은 자동 변경하지 않는다.
- 가격 관측값이 없으면 표준품목은 유지하되 내부 표준가격은 없다고
  표시한다.
- 새 구축 실행이 실패해도 직전 성공 표준 DB는 계속 조회 가능하다.
- 원본 견적과 append-only 결정·가격 버전은 삭제하거나 덮어쓰지 않는다.

## 9. 검증 및 완료 조건

- 기존 `표준단가DB.xlsx`를 읽거나 요구하는 운영 코드가 없다.
- `/reconciliation` 경로와 메뉴가 없다.
- 엑셀 내보내기 기능이 없다.
- 기존 과거 견적 문서만 `HISTORICAL_REFERENCE`로 표준 DB 구축에
  사용된다.
- 신규 업로드 문서는 `INCOMING_BID`이며 표준 DB 가격에 섞이지 않는다.
- 최신 `INCLUDED` 행 중 품명 키가 있는 모든 행이 표준품목 소속 또는
  명시적인 충돌 상태로 설명된다.
- 근거 1건 그룹도 표준품목과 표준가격이 생성된다.
- 동일 입력 재실행에서 신규 표준품목·소속·가격 버전이 0건이다.
- 그룹 구성이나 가격 변경 시에만 새 버전이 생성된다.
- 표준가격에서 원본 파일·시트·행 또는 PDF 페이지까지 역추적된다.
- 신규 견적 업로드 후 내부 표준가격에 따른 품목별·전체 판정이 웹에
  표시된다.
- 백엔드 전체 테스트, Alembic 왕복·스키마 검사, 프런트엔드 전체
  테스트와 프로덕션 빌드가 통과한다.
- 서버 설치, hChat 실연결, DeviceMart·Mouser 시장가 연동은 후속
  단계로 유지한다.
