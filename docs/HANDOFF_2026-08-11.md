## 시장가 기능 사용법

1. `.env`의 `MOUSER_API_KEY`에 Mouser Search API 키를 입력한다.
2. 백엔드에서 `python -m alembic upgrade head`를 실행해 `0009`를 적용한다.
3. 신규 견적을 `/analysis`에 첨부한다.
4. 확정된 내부 표준가격이 없는 행의 `시장가 조회`를 누른다.
5. 7일 이내 저장 결과가 있으면 캐시를 사용하고, 없거나 만료되면 DeviceMart와
   Mouser를 조회해 새 증빙을 저장한다.
6. 결과 카드에서 `원본 상품 보기`, `수집 증빙 보기`, 상품 사진과 수집 시각을
   확인한다.

시장가 데이터는 내부 표준단가 테이블과 분리되어 있으며
`backend/.local/evidence/market/`에 API JSON 또는 검색 JSON, 상품 이미지,
선택적 화면 캡처를 저장한다. DeviceMart는 공개
`/goods/search_sse_stream`의 `sphinx_result`만 사용하며 배너 HTML은 가격
근거로 사용하지 않는다. 두 출처가 모두 실패하거나 모델 토큰이 맞지 않으면
가격을 만들지 않고 판정대기로 둔다.

시장가 버튼은 내부 표준가격이 확정된 `MATCHED` 행에는 표시하지 않는다.
`NO_MATCH`, 유사 후보만 있는 `CANDIDATE`, 표준품목은 있으나 가격 근거가 없는
`MATCHED_NO_PRICE` 행에 표시한다. 결과 0건 캐시는 6시간만 유지하고, 상품이
있는 캐시는 7일간 사용한다. DB를 다른 PC로 옮겼을 때 대응 증빙 파일이 없으면

모델번호 또는 제조사 계열 식별 토큰으로 최대 2회 보완 검색하되, 일반 단어와
`200W` 같은 단순 측정값만으로는 결과를 확대하지 않는다. 정확한 모델 토큰이
없는 제조사·제품군 검색 결과는 참고 후보와 가격만 표시하고 자동 고가·저가

## 다른 PC에서 pull 후 실행·데이터 갱신

운영 SQLite DB `backend/.local/standard-item-migration-v2.sqlite3`는 저장소에
함께 관리한다. pull 후 별도 재구축 없이 같은 데이터로 시작하며, 실행 보고서와
백업 DB만 로컬 전용이다. 명령은 저장소 루트의 `cmd.exe`에서 실행한다.

```bat
git switch feature/market-price-integration
git pull origin feature/market-price-integration

py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -e backend
call npm.cmd --prefix frontend install
scripts\install-ocr-runtime.bat

scripts\start-local.bat --validate-only
scripts\start-local.bat
```

새 원본이나 보안해제본을 추가한 경우에만 다음을 실행한다.

```bat
scripts\start-local.bat --refresh-data
```

`--refresh-data`와 `--initialize-only`는 다음 작업을 순서대로 수행한다.

1. 기존 운영 DB의 SQLite 백업 자동 생성
2. Alembic 최신 마이그레이션 적용
3. `견적서/` 아래 새 파일만 지문 기준 증분 적재와 정제
4. 최신 `INCLUDED` 행으로 표준품목과 표준가격 갱신
5. 3차 원본 677개 메타데이터 감사
6. 표준 DB와 메타데이터 감사 보고서 저장

OCR 행과 표 구조가 불명확한 행은 자동 표준가격에 들어가지 않는다. 웹의
`정제 검토`에서 원본을 확인하고 포함 결정을 해야 다음 갱신에 반영된다.

사내에서 보안해제본을 받을 때는 원본을 덮어쓰지 말고 파일명 뒤에
`_보안해제`를 붙여 같은 견적 묶음 폴더에 둔 뒤 `--refresh-data`를 실행한다.
보호본과 해제본은 같은 문서 그룹으로 묶고, 실제 품목행은 해제본에서 읽는다.

완료 후 화면 실행:

```bat
scripts\start-local.bat
```

확인 주소:

- 웹 분석: `http://127.0.0.1:4173/analysis`
- API 상태: `http://127.0.0.1:8000/api/health`
- 운영 DB 기준: 표준품목 7,033개, 원본 행 55,650개

완전 재구축이 필요해도 운영 DB를 삭제하지 않는다. 운영 DB 복사본에서 먼저
파서 결과와 신규 견적 이력 보존을 확인한 뒤 승격한다.

## 3차 원본 메타데이터 감사와 누락값 처리 (2026-08-11)

실행기는 DB 마이그레이션과 표준 DB 확인 후 3차 학습 원본 메타데이터 감사를
자동 실행한다. 이미 같은 SHA와 규칙 버전으로 감사한 파일은 다시 파싱하지
않으며, CSV만 동일 결과로 갱신한다.

수동 실행:

```bat
set "DATABASE_FILE=%CD%\backend\.local\standard-item-migration-v2.sqlite3"
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m app.metadata_audit.cli --quote-root "%CD%\..\견적서" --database-file "%DATABASE_FILE%" --report ".local\reports\third-training-metadata-audit.csv"
cd ..
```

결과 파일:

```text
backend\.local\reports\third-training-metadata-audit.csv
docs\DATA_QUALITY_AUDIT_2026-08-11.md
```

- `OPENED`: 파일을 열어 텍스트 또는 셀을 확인했다.
- `FAILED`: DRM·손상·인코딩 문제로 열지 못했다. 보안 해제본 또는 정상
  복사본을 받은 뒤 같은 명령으로 재감사한다.
- `UNSUPPORTED`: 메타데이터 감사기가 헤더 정보를 해석하지 못한 형식이다.
  품목 적재에서는 JPG를 OCR 검토 대상으로, ZIP 내부 XLS/XLSX를 안전 제한
  안에서 별도로 처리한다. ECML 포인터 2개는 가격 근거로 사용하지 않는다.
- `OCR_REQUIRED`: 파일은 열리지만 텍스트가 없어 이미지 확인이 필요하다.
- `REVIEW_REQUIRED`: 공급사와 견적일을 모두 확정하지 못했다. 임의 추정값을
  넣지 않는다.

팀 `표준단가DB.xlsx`의 `바츠추출`, `AONE협력사`는 공급사로 가져오지 않는다.
원본의 명시된 라벨과 위치가 있는 필드만 반영하고, 확인되지 않은 값은 화면에
`원본에서 확인되지 않음`으로 표시한다. 세부 감사 수치와 재구축 비교는 위
데이터 품질 감사 문서를 기준으로 한다.

현재 운영 DB는 기존 DB 복사본에서 신규 견적 6,529행 보존, SQLite 무결성,
오탐 차단과 전체 테스트를 확인한 뒤 승격했다. 갱신 전 백업은 로컬의
`backend\.local\backups\standard-item-migration-v2.before-operational-refresh-*.sqlite3`
형식으로 남는다. 백업 파일은 Git에 올리지 않는다.
