# 3차 학습 원본 및 표준 DB 데이터 품질 감사

기준일: 2026-08-11

## 결론

팀 최신 `표준단가DB.xlsx`는 운영 DB의 공급사·제조사·견적일을 채우는
자료나 재구축 결과의 정답으로 사용하지 않는다. 원본 견적서에서 위치까지
확인되는 값만 운영 메타데이터로 반영한다.

팀 엑셀 원본데이터 17,872행 중 13,626행(76.24%)의 공급사 값은 실제
업체명이 아니라 `바츠추출` 또는 `AONE협력사`였다. 이 값들은 동일한
수집 묶음에 일괄 입력된 것으로 확인됐으며 운영 DB에서는 `수집 경로`로만
분리한다. 요약 시트의 `주요메이커`는 그룹 첫 행, `최근견적일`은 문자열
최댓값으로 생성되어 실제 대표 제조사·최신 날짜를 보장하지 않는다.

열기 실패 57개는 PDF 내부 구조 오류·DRM 헤더, 손상된 Excel/ZIP 구조,
문자 인코딩 오류로 분류됐다. 파일을 삭제하거나 임의값으로 보완하지 않고
감사 보고서에 실패 원인을 남긴다.

감사 원문은 다음 로컬 파일에 저장된다.

```text
backend\.local\reports\third-training-metadata-audit.csv
```

CSV에는 파일별 열림 상태, 추출 방식, 공급사·견적일·공사명 후보,
시트·셀 또는 PDF 페이지, 신뢰도, 수집 경로가 기록된다. 동일 파일 SHA와
규칙 버전으로 다시 실행하면 후보·메타데이터 버전은 중복되지 않는다.

## 파싱 및 재구축 검증

아래 수치는 추가 파서·OCR 적용 전 기준선 검증 결과다. 최종 운영 수치는
다음 `추가 회수 및 운영 반영 결과` 절을 따른다.

- 3차 학습 원본을 기존 DB와 독립된 복사본에서 다시 적재한 결과 원본 행은
  기존과 재구축 모두 18,592행이며 필드 단위 차이는 0건이었다.
- 3차 원본의 규격 값 보유 행은 6,558/18,592행(35.27%), 제조사 값 보유
  행은 1,112행이었다. 제조사 열에서 인건비·작업 설명 문구가 들어간 사례는
  제외 규칙으로 차단했다.
- 실제 677개 원본 중 정확히 `장치`와 `내용` 헤더를 함께 가진 Excel은
  발견되지 않았다. 해당 양식 지원은 회귀 테스트로 보장하되, 팀 엑셀의
  `FRAME/SUPPORT` 사례를 실제 원본 복구 성과로 과장하지 않는다.
- 독립 재구축 DB는 과거 견적만으로 원본 행 26,456건, 표준 품목 6,943건,
  가격 근거 18,607건을 만들었다. 근거 1건 품목은 4,237건, 단위 충돌은
  274건이었다.
- 운영 DB를 복사한 검증 DB에 추가 파서와 OCR을 적용한 뒤 신규 견적 접수
  이력 6,529행이 그대로 유지되는 것을 확인했다. 검증 DB의 무결성과 핵심
  테이블 건수가 일치한 후 운영 경로로 승격했다.

`견적서\복구본\3차 학습\`에 저장했다. 나머지 53개는 사내에서 보안해제본

포인터 파일이므로 자동 가격 근거로 사용하지 않는다.

규격 미표시는 앞으로 `원문에 규격 없음`, `견적서에서 규격 위치 확인 필요`,
`원본 상태 확인 필요`로 구분한다. 화면에서 단순 `—`로 표시하지 않는다.

## 운영 원칙

1. `AONE`, `바츠`는 공급사가 아니라 수집 경로다.
2. `미확인`, 임시 날짜 `2025-01-01`, 파일명·폴더명 추정값은 통계에서
   제외한다.
3. 명확한 라벨과 원본 위치가 있는 개별 필드만 자동 반영한다.
4. 원본 공란과 파서 누락을 별도 상태로 관리한다.
5. 재구축은 운영 DB를 삭제하지 않고 복사본에서 먼저 검증한다.
