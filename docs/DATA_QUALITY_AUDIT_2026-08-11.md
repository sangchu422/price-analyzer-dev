# 3차 학습 원본 및 표준 DB 데이터 품질 감사

기준일: 2026-08-11

## 결론

팀 최신 `표준단가DB.xlsx`는 가격·공급사·제조사의 입력이나 재구축 결과의
정답으로 사용하지 않는다. 다만 동일 원본에서 생성된 `원본견적데이터` 시트의
견적일은 출처 파일이 현재 원본과 일치할 때만 날짜 보완 근거로 사용할 수 있다.

팀 엑셀 원본데이터 17,872행 중 13,626행(76.24%)의 공급사 값은 실제
업체명이 아니라 `바츠추출` 또는 `AONE협력사`였다. 이 값들은 동일한
수집 묶음에 일괄 입력된 것으로 확인됐으며 운영 DB에서는 `수집 경로`로만
분리한다. 요약 시트의 `주요메이커`는 그룹 첫 행, `최근견적일`은 문자열
최댓값으로 생성되어 실제 대표 제조사·최신 날짜를 보장하지 않는다.

## 팀 엑셀 최근 견적일 재검증

- `표준단가DB` 시트 K열 6,102건은 유효 날짜 4,400건, `미확인` 1,702건이다.
- K열은 `품명 + 규격 + 단위` 그룹의 견적일 문자열에 단순 `max()`를 적용해
  만들어졌다. 이 때문에 실제 날짜가 있어도 한 행에 `미확인`이 섞이면
  `미확인`이 최신값으로 선택된 그룹이 244건이다.
- 따라서 K열을 DB에 직접 복사하지 않는다. `원본견적데이터` D열과 동반 JSON의
  `출처파일`을 현재 `source_variant` 경로와 일대일 대조한다.
- 175개 팀 원본 중 현재 DB와 166개가 연결됐다. 52개 AONE 원본은 날짜가
  `미확인`, 2개 임시 날짜 `2025-01-01`은 제외했다.
- 현재 DB에 날짜가 없던 원본 83개를 보완 대상으로 확인했다. 이미 원본에서
  확인한 날짜와 다른 27개는 기존 값을 유지하고 충돌 보고서에 남긴다.
- 바츠 자료의 날짜는 견적서 본문이 아니라 파일명 앞자리의 수집 시각에서
  생성된 값이다. DB에는 `FILE_DATE_INFERRED`로 근거를 남기고 화면에서는
  일자를 확정값처럼 보이지 않게 `YYYY년 (파일명 기준)`으로 표시한다.
- 1·2차 수작업 메타데이터는 `REFERENCE_BACKFILL`로 구분한다. 원본에서 직접
  확인된 기존 날짜는 `CONFIRMED`이며 가장 우선한다.

재실행 가능한 명령과 결과 보고서는 인수인계 문서의
`팀 엑셀 견적일 보완` 절을 따른다.

## 과거 견적 본문·머리말 날짜 재확인

- 운영 DB의 과거 견적 문서는 483개이며, 482개는 직접 열렸다. ZIP 1개는
  날짜 감사 대상 형식이 아니므로 수동 확인 상태로 유지했다.
- 표지·머리말과 본문에서 견적일 후보가 확인된 문서는 232개다. 기존 팀
  엑셀 대조 날짜까지 합쳐 최종 날짜 보유 문서는 147개에서 287개로 늘었다.
- 새로 날짜가 생긴 문서는 140개다. 기존 팀 엑셀 날짜와 원본 표지 날짜가
  달랐던 12개는 원본 표지의 실제 견적일로 정정 이력을 추가했다.
- 표준 DB 재계산 후 날짜가 표시되는 표준 품목은 4,317개에서 5,174개로,
  날짜가 연결된 최신 가격 근거는 12,458개에서 15,632개로 늘었다.
- 텍스트가 없던 PDF 5개는 표지 2쪽을 OCR하고 원본 이미지로 재확인했다.
  `DATE` 또는 견적서 표지의 단일 날짜만 반영했으며 `Validity` 날짜는
  제외했다.
- 견적번호 내부의 8자리 숫자, 납기·유효기간·결제일, 상세 페이지의 별도
  작성일은 자동 기준일에서 제외한다.
- 날짜를 확인하지 못한 196개 문서는 추정값으로 채우지 않는다. 향후 정상본
  또는 보안해제본이 추가되면 같은 감사 명령을 재실행한다.

감사 보고서는 다음 로컬 파일에 저장된다.

```text
backend\.local\reports\historical-source-date-audit.csv
```

## 파싱 및 재구축 검증

아래 수치는 추가 파서·OCR 적용 전 기준선 검증 결과다. 최종 운영 수치는
다음 `추가 회수 및 운영 반영 결과` 절을 따른다.

- 3차 학습 원본을 기존 DB와 독립된 복사본에서 다시 적재한 결과 원본 행은
  기존과 재구축 모두 18,592행이며 필드 단위 차이는 0건이었다.
- 3차 원본의 규격 값 보유 행은 6,558/18,592행(35.27%), 제조사 값 보유
  행은 1,112행이었다. 제조사 열에서 인건비·작업 설명 문구가 들어간 사례는
  제외 규칙으로 차단했다.
- 실제 677개 원본 중 정확히 `장치`와 `내용` 헤더를 함께 가진 Excel은
  발견되지 않았다. 해당 양식 지원은 회귀 테스트로 보장하되, 팀 엑셀의
  `FRAME/SUPPORT` 사례를 실제 원본 복구 성과로 과장하지 않는다.
- 독립 재구축 DB는 과거 견적만으로 원본 행 26,456건, 표준 품목 6,943건,
  가격 근거 18,607건을 만들었다. 근거 1건 품목은 4,237건, 단위 충돌은
  274건이었다.
- 운영 DB를 복사한 검증 DB에 추가 파서와 OCR을 적용한 뒤 신규 견적 접수
  이력 6,529행이 그대로 유지되는 것을 확인했다. 검증 DB의 무결성과 핵심
  테이블 건수가 일치한 후 운영 경로로 승격했다.

## 운영 원칙

1. `AONE`, `바츠`는 공급사가 아니라 수집 경로다.
2. `미확인`, 임시 날짜 `2025-01-01`은 제외한다. 파일명 추정 날짜는
   확정 일자로 집계하지 않고 연도 보정용 저신뢰 근거로만 구분한다.
3. 명확한 라벨과 원본 위치가 있는 개별 필드만 자동 반영한다.
4. 원본 공란과 파서 누락을 별도 상태로 관리한다.
5. 재구축은 운영 DB를 삭제하지 않고 복사본에서 먼저 검증한다.
