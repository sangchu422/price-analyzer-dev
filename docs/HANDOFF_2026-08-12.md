## 운영 가격의 기준

- 표준 DB의 원천은 정제 완료된 과거 견적 원본이다.
- 동일 복사본은 1건만 가격 통계에 기여한다. 다른 복사본의 raw ID는 대표
  관측의 감사 이력에 함께 연결된다.
- 명시적인 동일 개정 계열은 원본 확인 최신 견적일, 최신 개정번호, 정상 파싱
  원본, 최근 수집본 순으로 대표를 고른다.
- 값이 다르고 개정 관계가 불명확한 견적은 임의로 합치지 않는다.
- 운영 화면과 신규 견적 분석은 현재 입력·계산식·코드 지문이 모두 같은 성공
  빌드의 투영 결과만 사용한다.
- 빌드가 현재 코드와 맞지 않으면 마지막 가격을 신규 판정에 쓰지 않고
  `재구축 필요`라고 설명한다. 근거를 `0건`으로 오인해 표시하지 않는다.

## 구매 목표가 계산

신규 분석은 KOSIS 소비자물가 등락률 `총지수`를 사용한다.

| 항목 | 고정값 |
|---|---|
| 기관 | `101` |
| 통계표 | `DT_1J22041` |
| 항목 | `T` |
| 분류 | `0` |
| 주기·단위 | 연간·`%` |
| 공식 화면 | <https://kosis.kr/statHtml/statHtml.do?orgId=101&tblId=DT_1J22041> |

계산식은 다음과 같다.

```text
누적 물가계수 = ∏(1 + 연도별 총지수 등락률 / 100)
적용 연도 = 견적연도+1 ~ 마지막 확정연도
보정 단가 = 과거 개당 단가 × 누적 물가계수
구매 목표 단가 = 보정 단가들의 중앙값
```

2016년 1,000,000원에 2017~2025년 확정값을 적용하면 약 1,216,544원이다.
중간 계산은 Decimal 정밀도를 유지하고 최종 단가·금액만 원 단위로 반올림한다.
연도 중 하나라도 빠지면 다른 지수로 대체하지 않고 `연간 소비자물가 자료
누락`으로 표시한다. 2026년 연간 값이 미확정인 동안 화면에는 `2025년 확정
소비자물가 기준`이라고 표시한다.

과거 생산자물가지수 분석 실행은 재현을 위해 남아 있으나, 새 분석 실행에는
사용하지 않는다.

## 시장가 자동 보완

신규 견적의 각 항목은 다음 순서로 처리한다.

```text
활성 표준 DB
→ 유효한 시장가 캐시
→ DeviceMart·Mouser 실시간 조회
→ 시장가 확인 불가·판정 대기
```

- 표준가격이 있으면 외부 조회를 생략한다.
- 정제 완료 품목만 자동 조회한다.
- 한 번에 최대 4개 품목을 처리하며 출처별 요청 제한은 15초다.
- 로컬 SQLite에서는 조회 결과 저장 충돌을 막기 위해 품목별 저장을 직렬화한다.
  서버형 DB에서는 최대 4개 병렬 처리를 유지한다.
- 정확한 모델번호, 제품 제조사, 수량·MOQ, 재고 조건이 확인된 상품만 자동
  가격 판정에 사용한다.
- 유사 상품, 개발보드·키트, 제조사 불명, 재고 불명 결과는 가격 근거로
  만들지 않고 참고 링크로만 표시한다.
- Mouser 키가 없으면 DeviceMart만 조회하고 Mouser 미설정 상태를 함께
  남긴다.
- 수집 결과와 원본 링크·증빙은 기존 시장가 캐시에 보존되므로 새로고침 뒤에도
  다시 사용할 수 있다.

## 화면 변경

- `공급사`는 `견적 제출사`, `제조사`는 `제품 제조사`로 표시한다.
- 표의 머리글은 가운데 정렬하고 품명 본문만 좌측 정렬한다.
- 신규 견적의 `견적 단가`는 `개당 단가`, `견적 금액`은 `구매 금액`으로
  바꿨다.
- 단위 뒤 수량이 없을 때 `EA · —`처럼 표시하지 않고 `EA`만 보인다.
- 참조 단가는 `최저 / 기준 / 최고`로 구분한다.
- 구매 목표가 상세에는 적용 연도별 등락률, 누적 상승률, 보정계수를 표시한다.
- 정제 검토 원본 미리보기에는 실제 헤더를 최대 4행까지 포함하고 대상 행을
  강조한다.
- 금액 불일치는 원본 수량, 개당 단가, 표시 금액, 계산 금액, 차액·차이율,
  허용 오차를 한 화면에서 확인할 수 있다.

실제 브라우저에서 시연용 견적서를 다시 분석해 다음을 확인했다.

- 표준 DB 매칭 품목은 외부 조회를 생략한다.
- 미매칭 2개 중 DeviceMart 유사품 확인 1개는 참고가로만 표시하고, 실제 근거가
  없는 1개는 판정 대기로 유지한다.
- 로컬 SQLite 동시 저장 오류와 브라우저 콘솔 오류는 발생하지 않았다.
- 구매 목표가 탭에서 적용 연도별 소비자물가 등락률, 누적 상승률과 보정계수를
  원본별로 확인할 수 있다.
- 정제 검토에서 금액 불일치 계산값과 원본 표 헤더·대상 행 강조가 표시된다.

## 다른 PC에서 갱신하는 순서

아래 명령은 저장소 루트에서 실행한다. 먼저 Python 가상환경과 프런트 패키지를
설치하고 `.env`의 로컬 경로·선택형 API 설정을 확인한다.

1. 마이그레이션 확인

```bat
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m alembic check
```

2. 표준 DB 재구축

```bat
..\.venv\Scripts\python.exe -m app.cli standard-db-build --database-file .local\standard-item-migration-v2.sqlite3 --report .local\reports\standard-db-build-20260812.json --json --actor local-operator
```

동일 입력·계산식·코드로 다시 실행하면 기존 성공 빌드를 재사용한다. 보고서의
`rebuild_required_count`가 0이 아니면 실제 업무 판정을 진행하지 말고 보고서와
DB 백업을 보존한 채 원인을 확인한다.

3. API를 실행한 뒤 소비자물가 캐시 갱신

```bat
curl -X POST http://127.0.0.1:8000/api/analysis/inflation/series/cpi-all/sync
```

응답에서 다음을 확인한다.

- `series_kind`: `CPI_ALL`
- `table_id`: `DT_1J22041`
- `item_id`: `T`
- `classifier_code`: `0`
- `latest_confirmed_year`: 마지막 확정연도
- `annual_rates`: 연도별 총지수 등락률

갱신이 실패해도 기존 정상 CPI 캐시는 바뀌지 않는다. CPI 캐시가 전혀 없으면
구매 목표가는 `소비자물가 갱신 필요`로 표시되고 생산자물가로 대체되지 않는다.

4. 검증

```bat
cd backend
..\.venv\Scripts\python.exe -m pytest -q
cd ..\frontend
npm.cmd test -- --run
npm.cmd run lint
npm.cmd run build
```

## 장애 시 복구 원칙

- 실제 DB에 적용하기 전에 `backend/.local/backups/` 아래에 SQLite 파일을
  복사해 둔다.
- 빌드·CPI 동기화·분석 결과는 append-only다. 문제가 생겨도 과거 행을 직접
  삭제하거나 수정하지 않는다.
- 마이그레이션 또는 표준 DB 빌드가 실패하면 현재 DB를 덮어쓰지 말고 백업으로
  되돌린 뒤 실패 보고서를 확인한다.
- 시장가 출처가 일시적으로 실패하면 가격을 임의 생성하지 않는다. 캐시가
  없으면 판정 대기로 유지한다.
- 사내 전용 hChat API는 사내망에서만 별도로 시험하며 이번 변경의 표준가격,
  CPI 계산, 시장가 순서를 바꾸지 않는다.
