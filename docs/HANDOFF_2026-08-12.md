## 운영 가격의 기준

- 표준 DB의 원천은 정제 완료된 과거 견적 원본이다.
- 동일 복사본은 1건만 가격 통계에 기여한다. 다른 복사본의 raw ID는 대표
  관측의 감사 이력에 함께 연결된다.
- 명시적인 동일 개정 계열은 원본 확인 최신 견적일, 최신 개정번호, 정상 파싱
  원본, 최근 수집본 순으로 대표를 고른다.
- 값이 다르고 개정 관계가 불명확한 견적은 임의로 합치지 않는다.
- 운영 화면과 신규 견적 분석은 현재 입력·계산식·코드 지문이 모두 같은 성공
  빌드의 투영 결과만 사용한다.
- 빌드가 현재 코드와 맞지 않으면 마지막 가격을 신규 판정에 쓰지 않고
  `재구축 필요`라고 설명한다. 근거를 `0건`으로 오인해 표시하지 않는다.

## 구매 목표가 계산

신규 분석은 KOSIS 소비자물가 등락률 `총지수`를 사용한다.

| 항목 | 고정값 |
|---|---|
| 기관 | `101` |
| 통계표 | `DT_1J22041` |
| 항목 | `T` |
| 분류 | `0` |
| 주기·단위 | 연간·`%` |
| 공식 화면 | <https://kosis.kr/statHtml/statHtml.do?orgId=101&tblId=DT_1J22041> |

계산식은 다음과 같다.

```text
누적 물가계수 = ∏(1 + 연도별 총지수 등락률 / 100)
적용 연도 = 견적연도+1 ~ 마지막 확정연도
보정 단가 = 과거 개당 단가 × 누적 물가계수
구매 목표 단가 = 검증된 보정 단가들 중 최저값
```

2016년 1,000,000원에 2017~2025년 확정값을 적용하면 약 1,216,544원이다.
가격 적정성은 표준 DB 중앙값으로 판단하지만, 구매 목표가는 과거 실제 구매가 중
현재 가치로 환산한 최저값을 사용한다. 목표가 탭에는 별도 물가보정 기준가격을
노출하지 않고 계산 방식과 원본 근거만 접이식 상세로 제공한다.
중간 계산은 Decimal 정밀도를 유지하고 최종 단가·금액만 원 단위로 반올림한다.
연도 중 하나라도 빠지면 다른 지수로 대체하지 않고 `연간 소비자물가 자료
누락`으로 표시한다. 2026년 연간 값이 미확정인 동안 화면에는 `2025년 확정
소비자물가 기준`이라고 표시한다.

과거 생산자물가지수 분석 실행은 재현을 위해 남아 있으나, 새 분석 실행에는
사용하지 않는다.

## 시장가 자동 보완

신규 견적의 각 항목은 다음 순서로 처리한다.

```text
활성 표준 DB
→ 유효한 시장가 캐시
→ DeviceMart·Mouser 실시간 조회
→ 시장가 확인 불가·판정 대기
```

- 표준가격이 있으면 외부 조회를 생략한다.
- 정제 완료 품목만 자동 조회한다.
- 한 번에 최대 4개 품목을 처리하며 출처별 요청 제한은 15초다.
- 로컬 SQLite에서는 조회 결과 저장 충돌을 막기 위해 품목별 저장을 직렬화한다.
  서버형 DB에서는 최대 4개 병렬 처리를 유지한다.
- 정확한 모델번호, 제품 제조사, 수량·MOQ, 재고 조건이 확인된 상품만 자동
  가격 판정에 사용한다.
- 유사 상품, 개발보드·키트, 제조사 불명, 재고 불명 결과는 가격 근거로
  만들지 않고 참고 링크로만 표시한다.
- Mouser 키가 없으면 DeviceMart만 조회하고 Mouser 미설정 상태를 함께
  남긴다.
- 수집 결과와 원본 링크·증빙은 기존 시장가 캐시에 보존되므로 새로고침 뒤에도
  다시 사용할 수 있다.

## 정제 검토 오판 제거 및 전수 재평가 (2026-08-12)

파싱과 정제 규칙을 각각 `reader-v2`, `clean-v2`, `outlier-mad-v2`로 갱신했다. 과거
원본 행과 판정은 삭제하지 않으며, `source_parse_run`과 `source_parse_output`에서 원본별
최신 성공 파싱 결과만 운영 대상으로 선택한다. 재평가 결과는
`cleansing_reassessment_run/entry`에 append-only로 남는다.

주요 교정 내용은 다음과 같다.

- 엑셀 부동소수점 꼬리는 저장 정밀도 6자리에서 안전하게 반올림한다. 실제 숫자가 붙은
  파싱 오류나 의도적으로 입력한 과도한 소수 자릿수는 계속 검토 대상으로 둔다.
- 수량 0, 구매 금액 0, 유효한 개당 단가 조합은 정상으로 인정하며 개당 단가는 가격
  근거로 사용할 수 있다.
- 같은 행의 엑셀 곱셈 수식은 `일수 × 인원/수량 × 개당 단가`처럼 모든 인수를 읽어
  표시 금액과 비교한다. 임의 수식 실행은 하지 않는다.
- 제조사 복구 성공 자체는 검토 사유가 아니다. 실제 단가 편차 등의 사유와 제조사 복구
  이력을 분리한다.
- 단가 편차는 현재 단가, 중앙값, 차이율, 비교 관측값과 원본 위치가 저장된 경우에만
  사용자 화면에 표시한다.
- OCR·특수 PDF는 고신뢰 근거가 없으면 자동 포함하지 않고, 실패 원인을 숫자 미추출,
  개당 단가 미추출, 표 구조 불명확으로 구분한다.

전수 재평가와 감사 보고서는 다음 명령으로 다시 만들 수 있다.

```bat
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m app.cli ingest --quote-root ..\견적서 --database-file .local\standard-item-migration-v2.sqlite3 --report .local\reports\reader-v2-ingestion.json --json
..\.venv\Scripts\python.exe -m app.cleansing.reassess
..\.venv\Scripts\python.exe -m app.cleansing.audit
..\.venv\Scripts\python.exe -m app.cli standard-db-build --database-file .local\standard-item-migration-v2.sqlite3 --report .local\reports\standard-db-clean-v2.json --json --actor local-operator
```

`ingest`가 보안 파일, 누락 파일, 지원하지 않는 형식을 보고하며 종료 코드 1을 반환하는
것은 전체 트랜잭션 실패를 뜻하지 않는다. 보고서에서 각 문서 상태가 명시적으로 설명되는지
확인한다. 재평가 결과는 `backend/.local/reports/cleansing-reassessment-clean-v2.json`과
CSV에 저장된다. 과거 reader-v1 검토 행은 새 raw 행 또는 명시적인 미매칭 사유로 연결된다.

실제 DB 적용 전에 `backend/.local/backups/`에 SQLite 복사본을 만들고, 적용 후에는
`PRAGMA integrity_check`, `PRAGMA foreign_key_check`, 표준 DB projection의 근거 수·raw
ID·가격 통계 일치를 확인한다. 복구가 필요하면 실행 중인 백엔드를 종료한 뒤 현재 DB를
보존하고 백업 복사본을 원래 DB 파일명으로 복원한다.

판정 대기 2건으로 구성되며 구매 목표가는 22건에서 산정된다. 시연 시에는 이 파일을
`신규 견적 분석` 화면에 첨부하고 기본 임계치 10%/20%를 그대로 사용한다.
